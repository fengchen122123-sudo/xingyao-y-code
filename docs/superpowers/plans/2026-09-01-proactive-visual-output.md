# 主动可视化输出实施计划

> 背景：GUI 前端已支持 mermaid 渲染与 Markdown 图片内嵌展示，混元生图插件已可用；本计划让模型在不依赖用户开口的前提下主动判断何时配图，同时建立克制规则防止过度配图。

## 目标

- 让 AI 主动判断何时配图输出：架构/流程/时序类回答自动附 mermaid 图；用户明确要图时调用混元生图；网络结果带相关图片时自动下载内嵌，实现图文并茂。
- 通过明确的克制规则，保证纯编码、bug 排查、简单问答等场景不被图片干扰。

## 决策矩阵

### 判断时机（满足即配图）

| 场景 | 动作 |
| --- | --- |
| 回答涉及架构、流程、时序、状态机、层级或对比结构，且文字需描述三层以上关系 | 主动输出 ```mermaid 代码块（GUI 前端直接渲染） |
| 用户明确要求"画出来/生成图片/海报/封面/配图" | 调用 hunyuan_generate_image 生图，成功后用 ![](本地路径) 展示 |
| 简短示意图（≤6 个模块）且偏演示用途 | 先给 mermaid 精确版，可补一句"需要精美图片版可告诉我"，不默认生图 |
| fetch_url / search_news 结果中含与主题直接相关的图片 URL | 用 fetch_image 下载到本地后用 ![](本地路径) 内嵌展示 1~2 张；与主题无关的页面图片（广告、图标、头像）不下载 |

### 克制规则（触发即不配图/少配图）

| 规则 | 说明 |
| --- | --- |
| 数量上限 | 每个回复最多生成 1 张图片，mermaid 图不超过 2 个 |
| 不重复 | 同一主题已出过图就不要重复画 |
| mermaid 优先 | 能用 mermaid 表达就不用生图 |
| 场景排除 | 纯代码修改、bug 排查、简单问答、状态汇报不配图 |
| 用户否决 | 用户明确说"不要图/只给文字"时，本会话内停止一切主动配图 |

## 修改文件清单

- `system_prompt_gui.md`：在「# 终端输出」之后、「# 记忆」之前新增「# 主动可视化输出」章节（本计划对应的提示词改动）。
- `system_prompt.md`：同步加入同一章节，保持 CLI 与 GUI 行为一致。
- `plugins/hunyuan_image/plugin.py`：确认 hunyuan_generate_image 返回可用的本地路径，必要时补充保存路径约定与错误提示。
- `core/tools.py`：新增 fetch_image 工具，负责把图片 URL 下载到本地工作区并返回本地路径，供内嵌展示使用。

## 验证方式

1. 回归测试：
   - 后端运行 `pytest`，确认 fetch_image 工具注册与现有用例不回归。
   - 前端运行 `vitest`，确认 mermaid 渲染与图片内嵌展示相关组件不回归。
2. 实测对话三组：
   - 组一：询问分层架构问题，预期模型主动给出 mermaid 图且不调用混元生图。
   - 组二：明确要求"画一张海报"，预期调用 hunyuan_generate_image 并以 ![](本地路径) 展示。
   - 组三：纯代码修改任务，预期全程不配图；随后用户说"不要图"后再问架构问题，预期本会话内不再主动配图。

## 验收标准

- 四条判断时机与五条克制规则完整写入 system_prompt_gui.md 与 system_prompt.md，mermaid 代码块写法保持原样。
- core/tools.py 提供 fetch_image 工具并注册成功，hunyuan_generate_image 返回路径可被 Markdown 图片语法直接引用。
- pytest 与 vitest 全部通过，三组实测对话行为符合决策矩阵。
