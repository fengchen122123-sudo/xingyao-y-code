# Y-code CLI Hardening Design

## 1. 目标与范围

本项目逐项修复 CLI 只读审查中已经由源码调用链确认的问题，覆盖：

1. 权限绕过：受信任路径、命令会话授权、计划验证命令、动态 MCP 与 MCP 管理工具。
2. 数据安全：旧数据库破坏性初始化、撤销/检查点文件存在性、消息持久化失败。
3. 状态归属：排队消息、后台通知、子代理 undo/checkpoint 的 session/turn 绑定。
4. Headless 契约：入口参数、权限行为、退出码、本轮回复归属、stdout 纯净性。
5. 运行可靠性：SSRF、并行工具取消、后台进程追踪、记忆压缩并发提交、子代理并发槽。
6. 编辑确定性：删除无目标或模糊猜测式自动修改，只保留可证明唯一的编辑方式。

GUI 不在本次范围内；如果 CLI 核心模块被 GUI 共用，必须保持其已公开接口兼容，或同步调整调用方测试。

## 2. 全局约束

- 默认失败关闭：权限、路径、命令、迁移和网络目标无法证明安全时直接拒绝并报告原因。
- 不使用降级、兜底或启发式后处理掩盖错误；不确定的编辑必须失败。
- 不自动删除或覆盖无法迁移的数据；数据库不兼容必须保留原文件并给出可恢复路径。
- 每个生产代码变更先增加能复现原缺陷的测试，确认测试按预期失败后才实现修复。
- 每个任务独立提交并接受任务级代码审查；Critical/Important 审查意见必须闭环。
- 不依赖外网完成测试；涉及 HTTP、LiteLLM 和 MCP 的测试使用受控本地边界或依赖注入。
- 不修改用户已有未跟踪文件，不直接在 `master` 开发。
- 不在日志、工具结果、模型上下文或测试失败信息中暴露 API Key、token、password、cookie 或数据库内容。

## 3. 方案选择

采用隔离修复分支方案：`codex/cli-hardening` 位于独立 worktree，每个子系统形成可审查的小提交。

未采用直接在 `master` 修复，因为任务跨越多个共享模块且需要多轮回归。未采用只修 P0 的方案，因为会话错位、Headless 假成功和并发资源问题同样会造成数据或自动化结果不可信。

## 4. 权限与执行边界

### 4.1 路径信任

将“路径可读取”和“路径可写入”分离：

- Skill 目录仅允许无确认读取明确的 Skill 文档与其声明资源。
- `~/.ycode`、`~/.agents` 不再作为整目录可信白名单。
- `config.json`、`mcp.json`、数据库、系统提示词、凭据文件永远不因路径可信而免除保护。
- 沙盒外写入始终经过专用权限请求；可信读取规则不能影响写入。

路径判断必须使用解析后的绝对路径，抵抗 `..` 和符号链接逃逸。

### 4.2 命令授权

命令会话授权从字符串前缀改为结构化规则：

- 授权至少绑定可执行文件和首个子命令，例如 `git status`，不得折叠为 `git`。
- 含 shell 控制符、管道、重定向、换行或调用运算符的命令不允许保存为会话授权。
- 每个 shell 段必须单独授权；无法可靠解析时仅允许单次确认。
- 计划验证命令必须复用同一权限执行接口，不得直接 `subprocess.Popen(shell=True)`。

### 4.3 MCP

- 动态 MCP 工具默认视为有副作用并要求确认，除非 schema 中存在本系统认可的只读元数据。
- MCP 新增、删除、启停全部要求确认；新增时展示 command、args 和 env 键名，env 值不回显。
- MCP 配置写入改为进程内加锁的原子替换。
- 列表接口对所有 env 值统一输出 `<redacted>`，不按键名或长度猜测。

## 5. 数据安全与恢复

### 5.1 旧数据库

初始化不得 DROP 不兼容表。发现缺少核心列时：

1. 回滚当前事务。
2. 保持原数据库字节不变。
3. 抛出专用迁移错误，包含数据库路径、缺失列和人工恢复说明，但不包含数据内容。

如果后续掌握可证明的一对一旧 schema，再单独实现显式迁移命令；本次不猜测旧字段含义。

### 5.2 Undo 与 checkpoint

文件快照改为显式记录 `existed_before: bool` 与 `old_content: str`。空文件和不存在文件不能共用空字符串哨兵。

恢复操作必须检查每次写入的真实结果：失败不得计入成功。大文件恢复使用经过路径校验的原子恢复接口，而不是被普通覆盖保护拒绝后仍报告成功。

### 5.3 消息持久化

批量落库事务失败时保留待写队列，不得在 `finally` 无条件清空。重试必须具备幂等边界：同一进程内只在事务成功后从队列移除；不能声称部分提交，因为 `add_messages` 是完整事务。

## 6. Session 与 Turn 归属

引入明确的任务上下文值，至少包含：

- `session_name`
- `turn_id`
- `permission_owner`
- `cancel_event`

消息在进入队列时捕获 session，worker 不再读取执行时的全局 `current_session` 作为任务归属。后台子代理通知携带创建时的父 session。

子代理线程进入执行前同时绑定工具缓存、undo session 和 checkpoint turn；退出时在 `finally` 对称清理。checkpoint 存储按 `(session_name, turn_id)` 定位，不依赖一个可能被并行线程覆盖的全局单值。

## 7. Headless 契约

提供统一 `main_cli(argv=None) -> int`，由 console script 和 `python main.py` 共同调用。

Headless 每个任务使用独立结果对象：

- `success`
- `exit_code`
- `turn_id`
- `assistant_content`
- `error`

worker 必须把无模型、上下文构建失败、LLM `turn_error`、权限拒绝导致无法完成等状态写入该结果。`run_headless` 只打印本 turn 的回复，不再从整个 session 取最后一条 assistant 消息。

Headless 设置明确的 `ui_flavor=headless` 并通过 broker 自动拒绝权限，不允许回退到 `input()`。stdout 只包含最终回答；状态和错误写 stderr；不设置终端标题。

未知 CLI 参数必须返回非零，不使用 `parse_known_args()` 静默忽略。

## 8. 网络、取消与资源生命周期

### 8.1 SSRF

- 默认阻止 loopback、link-local、private、reserved、multicast 和云元数据目标。
- DNS 失败时拒绝。
- 使用自定义 redirect handler，在每次跳转前重新执行 URL 与 DNS 校验。
- fake-IP 或企业代理兼容只能通过显式 host allowlist，不再以关闭全局保护实现。

### 8.2 并行工具取消

并行批次改为 future 集合加短超时轮询；轮询期间检查 `cancel_event`。取消时取消未开始 future，并向已开始工具传播取消信号；主生成器不得等待全部 future 自然结束后才响应。

### 8.3 后台进程与子代理

- 后台任务只有在确认进程结束或确认 PID 已复用时才删除追踪记录；kill 失败必须保留记录。
- 子代理排队时间计入独立的 wall-clock 上限。
- 已进入 timed_out/cancelled 的执行不能永久占用并发许可；不可控模型调用需要明确 I/O 超时，仍无法终止的边界最终迁移到可终止子进程。

### 8.4 记忆压缩

session 增加内存或数据库 revision。压缩读取 snapshot 时记录 revision，提交摘要时执行 compare-and-swap；add、clear、undo 和摘要提交都会推进 revision。clear/undo 后旧压缩结果必须被丢弃。

上下文溢出后的重载必须使用 `get_history_for_llm()`，随后重新组装稳定 system prompt 与动态运行上下文，不能直接用原始 `get_history()` 覆盖消息。

## 9. 编辑确定性

`edit_file` 仅支持：

1. 唯一精确字符串匹配；允许规范化换行，但不允许字符相似度猜测。
2. 明确、有效的 1-based 行号范围。

缺少 target 和行号、目标不唯一、目标不匹配、文件在读取后变化时全部失败。模糊候选可以作为只读诊断提示，但不得写盘。

## 10. 测试与验收

每一项缺陷至少有一个直接回归测试，覆盖原始触发条件。重点验收包括：

- `git status` 授权不能放行 `git reset` 或 shell 串联。
- 沙盒外配置、数据库和系统提示词读写不能被 trusted path 绕过。
- 计划验证和 MCP 变更触发统一权限请求。
- 不兼容数据库启动不改变原文件。
- 空文件 undo 后仍存在且内容为空。
- 会话 A 入队后切换 B，消息仍属于 A。
- 子代理编辑能由父 turn checkpoint 恢复。
- Headless 所有失败返回非零且不打印旧回复或 OSC 控制符。
- 公网重定向到私网被拒绝。
- 并行工具取消在有阻塞任务时仍及时返回。
- kill 失败保留任务记录。
- clear/undo 后旧压缩结果不能重新写回。
- 持久化事务失败后待写消息没有丢失。
- 模糊或无目标编辑不修改文件。

验证分三层：

1. 每项 RED/GREEN 定向测试。
2. 每个子系统相关测试文件分组回归。
3. 最终全量 pytest；若全量套件仍超时，必须定位到具体测试文件和测试函数，不能把超时当作通过。

## 11. 实施分解

本设计拆成五个可独立审查的实施计划：

1. 权限、MCP 与 SSRF 边界。
2. 数据迁移、undo/checkpoint 与持久化。
3. session/turn、队列与子代理归属。
4. Headless 与 CLI 入口契约。
5. 取消、资源生命周期、压缩并发与确定性编辑。

各计划按上述顺序执行；前一计划暴露的公共接口作为后一计划的固定依赖。
