# 模型思考等级选择器设计

## 目标

在空状态输入框与正常对话输入框中，把思考设置从模型级联菜单移出，放到模型按钮右侧、发送按钮左侧。选择器按规范化后的模型名自动显示该模型真正支持的选项，不按供应商分组，也不让用户手工配置能力。

## 已确认的交互

- 保留“默认”选项。“默认”表示清除用户覆盖，采用模型自身默认行为。
- 可调模型显示脑图标、当前值和下拉箭头；弹层样式采用用户给出的紧凑单列菜单。
- 固定思考模型也显示按钮，文字固定为“开启”，按钮禁用，不打开菜单；悬停说明“该模型始终开启思考”。
- 未确认具有思考能力的模型不显示按钮。动态路由别名也不显示，避免把会变化的底层模型能力硬编码到路由名上。
- 选择显式强度时必须保证思考已开启。支持独立思考开关的协议同时发送开启参数；模型本身始终思考或强度字段本身即开关时，由其固定契约保证。绝不向不接受该字段的接口伪造参数。
- 选择“关闭”时关闭思考，并清除旧的强度覆盖，防止请求中残留互相冲突的参数。
- 非法或不受支持的选项由后端拒绝并返回错误；不得静默映射、降级或忽略。

## 能力模型

新增后端唯一能力注册表，以模型名为键。规范化只移除已知传输前缀（例如 `openai/`、`anthropic/`）并忽略大小写；不会把供应商作为能力判断条件。`zai-org/GLM-5.2` 作为 `glm-5.2` 的显式模型别名处理。

每个能力描述包含：

- `kind`: `effort`、`toggle`、`fixed` 或 `hidden`。
- `options`: 有序的可选值；固定或隐藏模型为空。
- `default`: 模型默认行为的显示说明，仅用于提示，不把“默认”转换成强制覆盖。
- `request_strategy`: 该模型的请求编码策略。

前后端统一使用以下内部值：`default`、`off`、`on`、`low`、`medium`、`high`、`xhigh`、`max`。中文标签分别为“默认、关闭、开启、低、中、高、超高、最高”。菜单只展示当前模型能力描述中的值。

## 后端结构

新增独立的思考能力模块，负责模型名规范化、能力查询、选项校验和当前选择解析。`core/model_catalog.py` 继续只保存预置模型目录，避免把同一能力重复写入多个供应商条目。

模型配置继续按模型 ID 持久化选择。选择值的状态转换如下：

| 选择 | 持久化与请求语义 |
|---|---|
| `default` | 清除用户的思考开关与强度覆盖，请求编码器采用该模型默认行为 |
| `off` | 显式关闭思考，清除强度覆盖 |
| `on` | 显式开启思考，不附加具名强度 |
| 具体强度 | 显式开启思考并保存强度，两项作为一个原子操作 |

后端桥接层在初始化、切换模型和切换会话响应中同时返回：

- 当前模型的能力描述；
- 当前有效选择；
- 固定模型的禁用原因。

设置接口接收新的通用选择值，按当前模型能力严格校验。固定、隐藏或不包含该值的模型直接返回失败，配置文件保持不变。

## 请求编码

请求构造层根据能力描述中的模型级策略编码，不能使用供应商名称决定菜单能力：

- 支持独立开关和强度的模型：显式强度同时生成“思考开启”和强度参数。
- 只有开关的模型：只生成开启或关闭参数，不生成强度。
- 强度字段自身表达开启状态的模型：`off` 使用其官方关闭值，具体强度使用官方强度值，不额外伪造不支持的开关键。
- 始终思考的模型：不接受设置调用；沿用其固定请求契约。
- `default`：不生成用户覆盖参数，沿用当前模型的内置请求契约。

构造完成后执行一致性检查：如果最终请求含强度，但模型既没有显式开启参数、也不是“始终思考”或“强度即开关”契约，则抛出错误，不发送请求。

该改动会触及 Provider 请求构造。实施前必须先运行 `tests/test_provider_payload_golden.py` 与 `tests/test_prompt_byte_stability.py` 建立原始基线；新增或修改黄金用例只能反映本设计明确要求的字段变化，不能为迁就实现改写无关字节。

## 前端结构与布局

新增可复用的 `ReasoningSelector` 组件，由 `InputArea.vue` 和 `KimiEmptyState.vue` 共用：

- 按钮位于模型按钮之后、发送按钮之前。
- 组件使用锚点定位并 Teleport 到 `body`，复用现有浮层主题、视口避让和全局点击关闭约定。
- 弹层为单列选项；当前项有勾选与高亮。
- 切换模型时关闭已打开的思考菜单，避免旧模型菜单继续可见。
- 固定模型渲染禁用按钮；隐藏模型完全不占布局空间。
- 正常输入框和空状态页的按钮尺寸分别继承各自现有控件体系，但菜单行为一致。

现有 `ModelCascader.vue` 底部通用“推理强度”行删除，模型级联菜单恢复为纯模型选择器。

## 数据流与失败处理

1. 后端根据当前模型名解析能力与当前选择，并随页面初始状态返回。
2. 前端 store 保存能力快照和当前选择，选择器据此渲染。
3. 用户选择后前端先乐观更新并关闭菜单，再调用后端设置接口。
4. 后端在同一配置更新中完成开关与强度变更。
5. 成功响应返回规范化后的选择与能力；失败时前端恢复旧值并显示错误。
6. 模型或会话切换响应覆盖能力快照与选择，确保每个模型展示自己的状态。

未知模型、能力表缺失、非法持久化值或不一致请求都显式暴露。不得回退到通用 `low/high/max`，也不得把错误配置静默解释成默认。

## 测试范围

- 能力模块：大小写、传输前缀、GLM 别名、所有预置模型分类和选项顺序。
- 配置层：默认、关闭、开启、具体强度的原子持久化；非法值不写盘。
- 请求层：显式强度必然开启思考；关闭不残留强度；固定模型契约不变；模型专属字段和值正确。
- 桥接层：初始化、模型切换、会话切换和设置接口均返回能力与当前选择。
- Store：切模型/会话同步状态、失败回滚、异步旧响应不覆盖新模型。
- 组件：位置顺序、固定模型禁用、隐藏模型不渲染、各模型菜单内容、选中态和关闭行为。
- 回归：前端全量测试与构建、Python 相关测试、Provider byte-golden、prompt byte-stability。

## 非目标

- 不提供用户自定义能力表。
- 不按供应商切换菜单内容。
- 不为动态路由探测底层模型。
- 不新增数值型 thinking budget 编辑器。
- 不展示模型内部思考正文或改变现有思考流渲染。
