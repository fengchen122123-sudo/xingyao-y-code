# Y-CODE Kimi 风格对话渲染设计

## 目标

在不改变启动 Logo、欢迎卡、主题、输入框和底部状态栏的前提下，将每轮对话渲染为清晰、稳定的终端历史：思考内容使用灰色，工具轨迹使用星瑶中文文案，最终正文使用结构化 Markdown 渲染，并保证标题、列表、代码块和表格规整可读。

目标版本为 `v1.0.9`。

## 非目标

- 不创建浏览器界面。
- 不增加独立思考边框或每块独立滚动区域。
- 不修改启动界面的结构、文案或视觉样式。
- 不在读取文件时输出源码正文。
- 不重构模型管理、权限模型、工具实现或数据库表结构。

## 每轮显示顺序

每轮对话按以下顺序写入终端历史：

```text
✨ You > 检查一下代码

• 灰色思考内容，实时追加……

● 星瑶正在查看文件：main.py
✓ 星瑶已查看文件：main.py（1769 行）

● 星瑶正在执行命令：pytest -q
✓ 命令执行完成

🤖 星瑶 >
结构化渲染后的最终回答
```

鼠标滚轮继续滚动 Windows Terminal 的完整历史，不启用 prompt_toolkit 全局鼠标捕获，以保留用户现有的终端文本选择习惯。

## 事件模型

模型网关必须将输出拆成互斥的公开事件：

- `thinking_started`：真实思考开始。
- `thinking_delta`：仅包含模型提供的思考文本。
- `thinking_finished`：真实思考结束。
- `assistant_delta`：仅包含最终公开回答，不包含 `<think>` 标签或思考正文。
- 工具、授权、错误和完成事件沿用现有事件类型。

模型原生 `reasoning_content` 直接转换为 `thinking_delta`。模型正文中的 `<think>` 或 `<thinking>` 必须通过支持跨分片标签的状态解析器转换为相同事件。解析器不得依赖一次分片包含完整标签，也不得把不完整标签泄露到终端。

没有可见思考输出的模型不产生空思考占位。思考可能是中文或英文，界面原样显示模型提供的内容，不做猜测式翻译或总结。

## 终端渲染

新增单一职责的终端 Markdown 渲染边界，最终回答完整缓冲后一次性渲染。这样可在已知完整结构后计算标题、列表、代码块和表格布局，避免流式分片破坏格式。

渲染规则：

- 思考：暗灰色，保持普通字形；中文不强制斜体。
- 最终正文：白色。
- 标题：白色高亮，并使用终端可读的层级间距。
- 列表：统一项目符号、缩进和换行。
- 行内代码、代码标识、文件路径和命令：青色。
- 代码块：保留缩进，按终端宽度裁定换行策略。
- 引用：灰色前缀和正文。
- 表格：由 Markdown 解析结果构造终端表格，根据当前终端宽度计算列宽；单元格过长时在单元格内换行，不能溢出或破坏边框。

渲染器使用结构化 Markdown API，不使用正则或字符串替换模拟表格。所有历史输出继续通过 `run_in_terminal()` 写入，防止 prompt_toolkit 重绘擦除内容。

## 工具轨迹

工具事件不渲染原始返回值，而是渲染稳定的中文摘要。工具名与文案的映射集中维护，避免分散条件判断。

主要文案：

| 工具 | 开始 | 成功 |
| --- | --- | --- |
| `read_file` | 星瑶正在查看文件：路径 | 星瑶已查看文件：路径（N 行） |
| `write_file` | 星瑶正在写入文件：路径 | 星瑶已写入文件：路径 |
| `edit_file` | 星瑶正在修改文件：路径 | 星瑶已修改文件：路径 |
| `execute_command` | 星瑶正在执行命令：命令 | 命令执行完成 |
| `list_directory` | 星瑶正在查看目录：路径 | 星瑶已查看目录：路径 |
| `glob_files` | 星瑶正在查找文件：模式 | 文件查找完成 |
| `search_code` | 星瑶正在搜索代码：关键词 | 代码搜索完成 |

开始状态使用绿色圆点或青色标记，成功使用绿色勾，失败使用红色叉。路径、命令、模式和关键词使用青色。`read_file` 的终端摘要只能包含路径和行数，严禁包含源码内容。

## 会话持久化与恢复

不新增数据库列。助理消息继续存储为 JSON 内容，但必须明确保存公开回答和可见思考，工具消息继续保存结构化工具调用结果。旧消息中的 `<think>` 内容在读取时兼容解析，新格式不再要求把标签混入公开回答。

切换或恢复会话时，历史渲染器复用与实时输出相同的颜色、工具文案和 Markdown 渲染逻辑，避免实时显示与历史显示不一致。旧会话缺少结构化思考字段时按现有内容解析；无法解析时只显示公开回答，不伪造思考内容。

## 系统提示词

活动系统提示词和仓库默认提示词同步更新：

- 终端已经支持标准 Markdown，不再禁止全部 Markdown。
- 鼓励使用简洁标题、列表、代码块和简单表格组织最终回答。
- 禁止 HTML、嵌套表格和依赖浏览器布局的语法。
- 工具执行完毕后必须给出最终中文结论。
- 不要求不支持推理通道的模型伪造思考内容。

## 错误处理

- 思考标签未闭合：本轮结束时仍归类为思考，不泄露到最终回答。
- Markdown 语法无效：结构化解析器明确报错并显示红色错误，不使用启发式后处理拼接格式。
- 表格无法在当前终端宽度下表达：单元格换行；列数本身无法容纳时明确显示渲染错误。
- 模型没有最终回答：沿用一次最终总结请求；仍无结果时显示本地检查摘要。
- 工具失败：显示红色失败轨迹，并把结构化错误保留给模型生成最终结论。

## 测试与验收

自动化测试覆盖：

- 原生 `reasoning_content` 被转换为 `thinking_delta`。
- 跨分片 `<think>` 标签不会泄露，且思考与公开回答严格分离。
- 每种核心工具的中文开始、成功和失败文案。
- `read_file` 摘要不包含源码。
- 标题、列表、代码块、引用和表格的终端渲染快照。
- 宽终端和窄终端下的表格列宽与单元格换行。
- 实时事件和历史会话使用相同渲染结果。
- 没有思考输出、没有最终回答、未闭合思考标签和工具失败场景。
- Windows PTY 端到端测试确认灰色思考、工具轨迹和白色最终正文真实出现在终端历史，且输入框恢复正常。

验收标准：

- 启动首屏与 `v1.0.8` 保持相同布局，仅版本号变为 `v1.0.9`。
- 每轮思考为灰色并保留在该轮历史中。
- 文件读取和写入只显示星瑶中文摘要。
- 最终正文无原始 Markdown 星号泄露，表格边框和单元格对齐稳定。
- 鼠标滚轮可滚动整个 Windows Terminal 历史。
- 全量 pytest 与语法编译检查通过。
