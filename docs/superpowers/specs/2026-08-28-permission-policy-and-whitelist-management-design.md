# 权限策略与白名单管理设计

## 背景

Y-CODE 已有 `confirm`、`accept_edits`、`plan`、`full` 四种权限模式、工作区沙盒、任务级内存授权以及按项目持久化的 `permissions.json`。现有实现仍有以下问题：

- 权限判断分散在 `core/llm.py`、Harness 工具管线、沙盒适配器和命令安全策略中，模式语义不易统一审查。
- `accept_edits` 目前只自动放行文件写改，所有命令都会询问，不能区分查询、普通变更和敏感操作。
- `full` 会放行删除、`git commit` 和 `git push` 等操作，灾难性命令则由另一层直接拒绝，缺少统一的决策原因。
- `plan` 会拦截所有需要权限的命令，无法自动执行明确的只读查询命令。
- 审批卡只有“本次”“拒绝”“始终允许”，没有把任务级临时授权和项目级持久授权明确区分。
- 设置页只能查看或清空项目白名单，不能手动新增和删除单条规则；CLI 同样缺少对应命令。

本设计将权限裁决集中到确定性的本地策略层，同时让 CLI 与 GUI 共享同一套规则管理接口。

## 目标

- 四种权限模式具有明确、可测试且前后端一致的行为。
- 查询操作自动放行；计划模式可以读取、查询和制定计划，但不能修改或删除工作区文件。
- 自动编辑模式自动执行普通变更，删除、Git 提交/推送等敏感操作必须询问。
- 完全访问模式在沙盒边界内放行所有非灾难性操作；解除沙盒限制后，工作区外也按完全访问语义执行。
- 灾难性命令在所有模式下直接拒绝，不能由审批、白名单或沙盒开关绕过。
- 审批同时支持本次、当前任务、当前项目三个授权层级。
- GUI 与 CLI 都能手动新增、单条删除、查看和清空项目白名单。
- 多任务并行时，任务级授权互相隔离；切换界面不会清除后台任务已有授权。

## 非目标

- 不引入操作系统级容器或新的进程沙盒。
- 不允许模型自由判断是否需要审批；最终裁决必须来自确定性的本地策略。
- 不把文件白名单扩展为目录递归授权。第一版继续使用精确文件路径，避免无意扩大写入范围。
- 不改变 MCP 启动白名单、凭据加密或插件信任机制自身的安全规则。
- 不改变 `permissions.json` 的现有版本和字段结构，不做破坏性迁移。

## 核心概念

### 风险等级

每次工具调用在执行前被分类为以下四类之一：

| 等级 | 含义 | 示例 |
|---|---|---|
| `query` | 不产生本地副作用的读取和查询 | 读文件、搜索代码、`git status`、`git diff` |
| `normal_mutation` | 范围明确、可审查的普通项目变更 | 写入文件、局部编辑、构建、格式化 |
| `sensitive_mutation` | 可能删除数据、发布状态或改变外部环境 | 删除、`git commit/push`、merge/rebase、安装依赖、终止进程、修改凭据 |
| `catastrophic` | 目标范围不可接受或载荷不可审查 | 格式化磁盘、递归删除根目录/工作区/用户目录、fork bomb、编码混淆执行、下载后直接管道执行 |

风险分类采用工具元数据和命令解析的组合：

- 内置读取工具继续使用 `ToolSpec.read_only`。
- 文件写入和编辑使用 `ToolSpec.mutates_files`，并结合目标路径判断沙盒边界。
- `execute_command` 由 `core.command_policy` 解析后动态分类。
- `manage_task(status/list)` 为查询，`manage_task(kill)` 为敏感操作。
- MCP 和插件工具默认沿用 `requires_permission`；无法证明只读时不得归入 `query`。
- 无法解析、含复合 shell、重定向、内联脚本或解释器显式覆盖的命令，绝不归入纯查询。

### 决策结果

策略层只返回不可变的决策对象，不直接显示 UI：

- `allow`：自动执行。
- `ask`：交给统一 Permission Broker，等待用户选择。
- `deny`：返回明确错误，不弹出可绕过的审批。

每个结果附带稳定原因码，例如：

- `catastrophic_denied`
- `plan_mutation_denied`
- `sandbox_boundary_requires_confirmation`
- `project_rule_hit`
- `task_grant_hit`
- `sensitive_requires_confirmation`
- `mode_default_allow`

原因码用于测试、日志和 UI 说明，不记录命令正文、工具参数、凭据或文件内容到 Harness Journal。

## 决策顺序

所有内置工具、MCP 工具和插件工具在真实执行前遵循同一顺序：

1. 严格解析工具和参数；解析失败直接报错。
2. 检测灾难性命令；命中后直接拒绝。
3. 应用计划模式写入门禁；计划模式下的工作区修改、删除和执行型命令直接拒绝。
4. 检查沙盒边界；沙盒限制开启且访问工作区外时进入边界审批。
5. 检查项目持久白名单。
6. 检查当前任务临时授权。
7. 根据权限模式和风险等级做默认决策。
8. `ask` 结果通过 Permission Broker 串行展示并等待用户回答。

项目白名单和任务授权不能绕过第 2、3、4 步。解除沙盒限制只移除工作区边界审批，不会改变当前权限模式本身。例如 `confirm` 模式即使解除沙盒限制，工作区外的写入仍因“变更前确认”而询问；`full` 模式解除沙盒限制后则自动放行所有非灾难性操作。

## 权限模式矩阵

| 操作 | `confirm` | `accept_edits` | `plan` | `full` |
|---|---|---|---|---|
| 查询与读取 | 自动放行 | 自动放行 | 自动放行 | 自动放行 |
| 文件写入、局部编辑 | 询问 | 自动放行 | 直接拒绝 | 自动放行 |
| 普通构建、测试、格式化命令 | 询问 | 自动放行 | 直接拒绝 | 自动放行 |
| 删除文件或目录 | 询问 | 必须询问 | 直接拒绝 | 自动放行 |
| `git commit`、`git push` | 询问 | 必须询问 | 直接拒绝 | 自动放行 |
| reset、merge、rebase、依赖安装、终止进程等敏感操作 | 询问 | 必须询问 | 直接拒绝 | 自动放行 |
| 灾难性命令 | 直接拒绝 | 直接拒绝 | 直接拒绝 | 直接拒绝 |

沙盒限制开启时，工作区外访问在上述模式决策之前询问。沙盒限制解除后不再进行边界询问，但仍执行表中的模式规则。

### 查询命令识别

只读命令使用明确的命令族规则，不根据自然语言或模型声明判断。首批规则覆盖现有开发场景，包括但不限于：

- Git：`status`、`diff`、`log`、`show`、`rev-parse`、`ls-files`，以及参数受限的分支查询。
- 搜索和读取：`rg`、`Get-Content` 及现有受支持的等价读取命令。
- 版本与帮助：安全命令的 `--version`、`-v`、`--help`、`-h` 查询。

只读规则必须检查完整 token，禁止简单字符串 `startswith`。带管道、重定向、命令连接符、命令替换、内联执行参数或未知 shell 语义时，分类不得为 `query`。

### 计划模式输出

计划模式允许读取工具、明确的只读查询命令、`plan_write`、`plan_read`、`plan_update`、`plan_retry` 和必要的用户澄清。计划元数据属于 Y-CODE 内部状态，不视为工作区文件修改。

动态运行上下文增加明确约束：计划模式的最终回答必须输出可执行计划，并说明实施前需要切换到其他权限模式。该约束进入动态上下文，不改动跨轮稳定前缀；不使用结果后处理伪造计划内容。

## 授权层级

### 允许本次

- 只允许当前一次真实工具调用。
- 不写入内存规则或磁盘。

### 本任务同类操作放行

- 绑定稳定的任务/会话 ID，而不是当前可见页面。
- 切换到其他任务后仍保留，原任务在后台继续执行时可以命中。
- 并行任务分别存储，互不继承。
- 关闭应用、删除任务或显式清除任务授权后失效。
- 安全、可分词的命令保存 token 前缀；复合命令和内联脚本只能保存当前任务内的精确命令，不扩展为前缀。
- 文件写入和编辑保存规范化后的精确文件路径。

### 加入项目白名单

- 按规范化工作目录写入 `permissions.json`，项目内所有任务共享，应用重启后仍生效。
- 命令使用安全 token 前缀匹配。
- 文件写入和编辑使用规范化后的精确绝对路径。
- 复合命令、重定向、内联脚本、解释器显式覆盖和灾难性命令不能持久化。
- 项目白名单可以覆盖 `confirm` 和 `accept_edits` 的普通或敏感审批，但不能覆盖灾难性拒绝、计划模式门禁和沙盒边界。

## 审批交互

普通权限请求在 CLI 和 GUI 中显示四个明确选项：

1. 允许本次
2. 拒绝
3. 本任务同类操作放行
4. 加入项目白名单

沙盒边界请求只显示：

1. 允许本次
2. 拒绝
3. 本任务内放行工作区外访问

沙盒边界不提供项目白名单选项；需要长期解除边界时使用 `/sandbox on` 或 GUI 沙盒开关。灾难性命令和计划模式禁止项不显示审批卡，直接返回拒绝原因。

Permission Broker 的选项语义从隐含索引改为集中定义的稳定枚举，CLI 和 GUI 都根据后端下发的选项渲染，避免前端自行推断索引含义。`ask_user` 保持自己的自定义选项协议，不与权限授权选项混用。

## 项目白名单管理

### 存储

继续使用现有 `permissions.json` v1 结构：

- `commands`: token 数组列表。
- `write_files`: 规范化绝对文件路径列表。
- `edit_files`: 规范化绝对文件路径列表。

`core.permission_store` 增加统一的增删接口，并保留现有函数作为兼容包装：

- `add_rule(rule_type, value, workdir=None)`
- `remove_rule(rule_type, value, workdir=None)`
- `add_command_rule`、`add_write_file`、`add_edit_file`
- `clear_project`

新增和删除在同一存储锁内完成读、校验、修改和原子写盘。写盘失败必须返回明确失败，GUI 和 CLI 不得显示成功。读取到损坏文件时继续采用最保守的空规则并记录警告，使权限回落到询问或拒绝，而不是错误放行。

### 规则校验

- 拒绝空值和未知规则类型。
- 命令规则必须通过现有安全分词器，并规范化为 token 元组。
- 拒绝复合命令、重定向、内联脚本、解释器显式覆盖和灾难性命令规则。
- 文件规则按当前线程工作目录解析相对路径，再做 `realpath + normcase` 规范化。
- 重复新增返回“规则已存在”，不重复落盘。
- 达到项目条目上限时明确报错，不静默丢弃新规则。
- 删除按“规则类型 + 规范值”精确匹配；不存在时返回“规则不存在”。

### GUI

“权限与沙盒”页面保留现有沙盒开关、当前权限模式和清空按钮，并增加：

- “添加规则”按钮。
- 规则类型选择：命令前缀、允许写入文件、允许修改文件。
- 规则内容输入框及保存、取消操作。
- 每条规则显示类型标签、规范值和单条删除按钮。
- 单条删除使用确认对话框；清空规则使用更醒目的二次确认。
- 新增、删除或清空成功后立即重新读取后端规则；失败时保留当前列表并显示真实错误。

GUI Bridge 增加：

- `add_permission_rule(rule_type, value)`
- `remove_permission_rule(rule_type, value)`

现有 `get_permission_rules` 和 `clear_permission_rules` 继续保留。所有接口使用当前项目的规范化工作目录，不接受前端传入任意项目键。

### CLI

`/whitelist` 支持以下子命令：

```text
/whitelist list
/whitelist add command <命令前缀>
/whitelist add write <文件路径>
/whitelist add edit <文件路径>
/whitelist remove command <命令前缀>
/whitelist remove write <文件路径>
/whitelist remove edit <文件路径>
/whitelist clear confirm
```

无参数时等同 `list`。路径和命令保留用户输入中的引号语义，由统一规则解析器校验。CLI 的新增、删除、重复和失败提示与 GUI 后端返回码一致。

## 错误处理

- 权限策略、存储和 Broker 异常不能伪装成用户拒绝。
- 无法分类时按保守规则询问或拒绝，不自动降级为允许。
- 持久化新增或删除失败时不得同步写入任务级授权来掩盖错误。
- UI 发送已失效审批请求时显示“请求已处理或失效”，不重放工具调用。
- 用户取消回合时，清理该回合未完成的审批；不自动执行、重放或提升授权。
- 白名单命中只影响授权，不跳过工具参数校验、沙盒路径规范化、命令灾难性检测或结果错误处理。

- 参数化覆盖四种模式 × 四种风险等级的完整矩阵。

5. 更新 GUI Bridge、审批卡和设置页，完成前端测试与构建。
6. 更新动态计划约束、README 和帮助文案，运行完整回归。

每一步只做范围明确、可独立验证的修改。实施时保留工作树中已有的无关变更，不覆盖、不回滚、不顺带重构。

## 验收标准

- CLI 与 GUI 对同一工具调用给出相同权限决策和授权选项。
- 自动编辑模式下普通编辑无需询问，删除和 `git commit/push` 必须询问。
- 计划模式可以执行明确查询，但无法修改、删除或通过白名单绕过门禁，最终回答输出计划。
- 完全访问模式在沙盒内自动执行所有非灾难性操作；解除沙盒限制后工作区外同样生效。
- 灾难性命令在任何模式和任何白名单状态下均被直接拒绝。
- 任务级授权不因切换界面失效，并行任务互不继承。
- 项目白名单既能通过审批自动写入，也能在 GUI 和 CLI 手动新增、单条删除及清空。
- 所有新增、删除、拒绝和失败都具有明确反馈，不存在静默降级或假成功。
