# Y-code 图片发送与对话内提示优化设计

## 目标

在不修改主模型、副模型及视觉路由配置的前提下，提高发送给视觉模型的图片质量与协议正确性，并将 GUI 的图片压缩结果从短时弹窗改为用户消息内的持久提示。

## 范围

- 优化 `core/input_parser.py` 的静态图片读取、方向校正、缩放、编码与大小控制。
- 保持 GIF 原样发送，不新增动图抽帧或视频处理。
- 保持现有 Base64 Data URL 传输方式，不接入厂商文件上传 API。
- GUI 将附件处理结果挂到对应用户消息；TUI 保持现有文本提示行为。
- 不修改 `supports_vision`、副模型选择或视觉副模型调用逻辑。

## 方案选择

采用“格式感知压缩 + 明确输出媒体类型 + GUI 专用内联事件”。

未采用的方案：

- 仅提高 `max_edge` 和 `quality`：改动小，但不能修复 PNG 内容与 MIME 不一致、透明背景和 EXIF 方向问题。
- 自动切图或 OCR：可能进一步提高超长截图识别率，但会引入图像类型判断、结果合并和额外模型调用，不属于本次最小范围。

## 图片处理设计

压缩函数返回图片字节和实际媒体类型，调用方不得再根据原文件扩展名猜测 MIME。

- 输入文件上限从 5 MiB 调整为 20 MiB，允许高清截图先压缩再判断输出大小。
- 解码后限制总像素数为 40,000,000，超过时明确拒绝，避免超大图片占满内存。
- 使用 `ImageOps.exif_transpose` 校正手机照片方向。
- 最大边默认从 1024 提升到 1536。
- JPEG/WebP 默认质量从 85 提升到 90；超过目标大小时按 5 递减至 50，选择第一个满足目标的结果；都不满足时选择体积最小的候选。
- PNG 保持 PNG 并使用 `optimize=True`，不把文字截图强制转换成 JPEG。
- 带透明通道的图片保持 PNG；只有输出格式明确为 JPEG 时才合成白色背景。
- GIF 原样返回并保持 `image/gif`。
- 压缩后比原图更大且原图不需要方向校正或缩放时，继续使用原图及其真实 MIME。

默认配置调整为：

```json
{
  "image_compression": {
    "max_edge": 1536,
    "quality": 90,
    "max_output_bytes": 1048576
  }
}
```

`max_output_bytes` 是质量目标，不是硬截断；无法在质量下限内达到目标时仍发送最小有效候选，并在提示中报告实际大小。

## GUI 事件与展示

`parse_user_input` 继续返回现有的附件提示字符串，避免修改 TUI 契约。GUI 桥接层不再把这些字符串作为 `notice` 弹窗发送，而是发送会话归属明确的 `user_attachment_notes` 事件。

前端收到事件后：

- 只处理当前会话事件。
- 从消息尾部向前找到最近一条用户消息。
- 将提示写入该消息的 `attachment_notes` 数组。
- 用户消息气泡在图片缩略图下方展示持久的附件处理说明。

没有可归属用户消息时抛出桥接契约错误，不静默丢弃。

## 错误处理

- 不支持格式、图片超限、像素超限和解码失败均返回明确附件提示。
- Pillow 不可用时明确报错，不再伪装成“已成功发送原图”。
- 输出 MIME 必须与编码内容一致；测试通过图片魔数和 Pillow 解码后的格式验证。

## 测试

- Python：PNG 保持 PNG、JPEG 渐进质量、EXIF 方向、透明 PNG、超大输入先压缩、像素上限、Data URL MIME 与内容一致。
- GUI 桥接：附件提示使用 `user_attachment_notes`，不再使用 `notice`。
- 前端 Store：提示挂到正确用户消息并按会话过滤。
- 前端组件：用户消息内渲染附件提示。
- 回归：完整 Python 相关测试、全部前端测试、TypeScript 检查与生产构建。

## 非目标

- 不修改视觉模型选择与副模型路由。
- 不增加远程图片 URL、文件上传 API、OCR 或自动分块。
- 不重构对话消息数据库结构；附件提示仅作为当前 GUI 消息状态展示。
