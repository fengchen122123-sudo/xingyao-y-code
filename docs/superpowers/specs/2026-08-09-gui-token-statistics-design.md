# GUI Token 统计页面设计

## 目标

在 GUI 设置页增加“Token 统计”入口，复用 CLI `/usage` 已持久化的真实 `token_usage` 数据，提供今日、近 7 天、近 30 天三个时间范围。页面既保留 CLI 的精确统计字段，又用每日圆环图直观展示多个模型在当天用量中的占比。

## 页面结构

设置页左侧导航保留“模型配置”，在其下新增“Token 统计”。统计页由四层组成：

1. 顶部标题、时间范围切换和刷新按钮。
2. 汇总卡片：总 Token、输入 Token、输出 Token、缓存命中，附请求次数与缓存命中率。
3. 每日用量：每天一张圆环卡片。圆环按模型切片，中心显示当天合计，卡片底部显示日期和请求次数。模型颜色在整个页面保持一致。
4. 模型明细：按总 Token 降序，显示模型、输入、输出、缓存输入、缓存命中率、请求数和合计。

近 30 天使用紧凑网格，零用量日期仍显示空环，使时间序列完整。没有任何历史记录时显示明确空状态，不虚构估算值。

## 数据口径

数据继续来自 `MemoryManager` 的 `token_usage` 表，不建立 GUI 专用统计表。新增按日期和模型聚合查询，字段为：

- `date`
- `provider`
- `model`
- `prompt`
- `completion`
- `cached`
- `cache_prompt`
- `total`
- `requests`

其中缓存命中率严格使用 `cached / cache_prompt`；provider 未报告缓存明细的请求不进入 `cache_prompt` 分母，与 CLI 当前口径一致。圆环按 `provider/model` 聚合不同 endpoint 和 scope，因为图表表达的是用户选择的模型用量；CLI 原有路由级查询保持不变。

桥接接口为 `get_token_usage_statistics(days)`，仅接受 `1`、`7`、`30`，返回完整日期序列、总体汇总和模型汇总。所有日期均使用本机时区，与写入 `token_usage.date` 的规则一致。

## 前端实现

Pinia store 保存统计快照、加载状态和当前天数。切换到统计页时加载近 30 天，切换范围或点击刷新时重新请求。

圆环不引入图表依赖。前端将模型比例转换成 CSS `conic-gradient`，并使用固定色板与稳定字符串哈希为同一模型分配相同颜色。每个圆环提供 `role="img"` 和包含日期、模型及用量的 `aria-label`。

数值显示使用 K/M/B 缩写帮助扫读，明细行通过 `title` 保留精确整数。颜色不是唯一信息载体：图例和明细均同时显示模型名称与数值。

## 错误处理

- 非法时间范围由后端明确返回 `{ok: false, msg}`。
- 数据库查询异常记录日志并返回失败，不用空数据掩盖错误。
- 前端请求失败保留上次成功快照并显示警告，不把旧数据误标为新范围。
- 空数据是正常状态，显示零值汇总、空圆环和“暂无记录”。

## 测试

- MemoryManager：验证跨天、跨模型聚合、请求计数和缓存分母。
- GUI bridge：验证日期补齐、汇总、模型排序与非法范围。
- Store：验证请求参数、成功快照和失败时保留旧数据。
- Vue：验证导航、范围切换、每日圆环、多模型图例、空状态及无旋转加载残留。
- 最终运行 Python 相关回归、全部前端测试、生产构建和 Playwright GUI 页面验证。

## 范围边界

本次不计算价格或费用，因为不同自定义模型的定价未被可靠配置；不增加导出、远程同步或自定义日期选择，避免与 CLI 已有三个主统计范围产生双重口径。
