# Y-code 执行中阶段汇报设计

## 背景

Y-code 已具备模型正文、思考、工具调用和工具结果的流式事件链路，但当前提示词同时要求长任务分阶段反馈，又要求把“让我先……”一类过程文字省略。模型通常选择更严格的后者，因此 GUI 中持续出现“思考过程 → 执行过程”，用户只能看到结构化工具轨迹，看不到 Codex 式的自然语言阶段汇报。

现有 GUI 还固定按“思考 → 执行过程 → 正文”渲染单个模型轮次。即使模型在工具调用前输出简短正文，执行卡片出现后也会排到正文上方，使视觉顺序与真实发生顺序相反。

## 目标

- 在长任务执行期间展示简短、面向用户的自然语言阶段汇报。
- 只在任务开始、关键发现、方案或阶段变化、较长验证前后汇报，不逐个工具播报。
- 每次汇报控制在一至两行，优先说明当前阶段以及下一步或关键发现。
- 保持私有思考不可见，不把分析链、自我对话或试误过程伪装成进度。
- GUI 中按“简短汇报 → 对应执行过程”的顺序展示工具调用轮次。
- GUI 与 CLI 使用一致的阶段汇报行为规则。

## 非目标

- 不展示或持久化模型私有思考正文。
- 不新增专用进度工具、事件类型或数据库表。
- 不修改 Harness 状态机、工具执行顺序、权限、取消或错误传播语义。
- 不修改 DeepSeek Prompt Ledger、工具 schema、Provider 请求组装或历史消息规范化。
- 不承诺对每个工具调用都产生汇报，也不以本地模板合成模型尚未确认的结论。

## 行为设计

### 汇报时机

模型应在以下关键边界输出一次公开进度：

1. 预计需要多个步骤或超过约十秒时，在第一批工具调用前说明当前阶段。
2. 发现会改变后续路径的关键事实后，说明发现及接下来的处理方向。
3. 从定位转入修改、从修改转入验证等阶段切换时，说明阶段变化。
4. 较长测试、构建或验证开始前说明验证目标；完成后只报告已由工具结果证实的状态。

以下情况不输出进度：

- 单次读取、搜索或其他低价值工具动作。
- “我在思考”“让我看看”“如果不行再试”等没有可验证信息的自我对话。
- 未经工具结果确认的成功、修复完成或测试通过结论。
- 能在很短时间内直接完成并给出最终答复的简单任务。

### 文案约束

- 每次一至两行，不写小标题和长列表。
- 使用“当前阶段/关键发现 + 下一步”结构，但不强制固定模板。
- 面向用户说明可观察事实和行动，不解释隐藏推理过程。
- 最终答复仍负责完整结论；阶段汇报不重复最终总结。

示例：

```text
我已确认问题在 GUI 的消息排列，不是流式事件丢失。接下来调整工具轮次的显示顺序并补回归测试。
```

```text

```

## 提示词设计

同步调整 `system_prompt_gui.md` 与 `system_prompt.md`：

- 保留“正文通道不得泄露内部推理”的安全边界。
- 明确区分“内部自我对话”和“面向用户的阶段汇报”；后者属于允许且必要的正文。
- 将现有“长任务分阶段反馈”要求具体化为关键时机、一至两行和禁止逐工具播报。
- 避免引入依赖当前目录、模型或权限的动态文字；规则仍是跨轮稳定内容。

本次只修改静态提示文件，不修改 `build_stable_system_message`、动态上下文、Provider 参数或工具列表。实施前必须先运行 Provider 请求 byte-golden 与 prompt byte-stability 回归，修改后再次运行同一组测试；禁止为迁就实现改写黄金字节。

## GUI 渲染设计

`MessageBubble.vue` 根据消息是否包含工具调用选择排列顺序：

- 工具调用轮次：思考块 → 阶段汇报正文 → 执行过程。
- 无工具调用的最终轮次：思考块 → 最终正文。
- 没有正文的工具轮次保持现有“思考块 → 执行过程”，不生成空白区域。

现有 `assistant_delta`、`round_started` 和工具事件已经能够支撑该行为，不新增事件或字段。`TurnGroup.vue` 继续在任务执行时实时展示中间轮次，并在任务完成后折叠中间过程、保留最终答复。

## 数据与兼容性

- 阶段汇报沿用普通 assistant `content` 流式传输和消息持久化。
- 同一轮的 `content + tool_calls` 仍按现有格式写入 `messages` 表。
- 历史会话无需迁移；旧消息若包含工具正文，会按新的正确时序展示。
- 工具调用、工具结果、思考内容和阶段汇报不做字符串猜测或后处理拼接。
- CLI 不需要新增渲染组件，只通过同步后的提示词获得相同行为。

## 验收标准

1. 多步骤任务会在关键阶段出现一至两行自然语言汇报，而不是只显示思考和执行卡片。
2. 连续读取、搜索等细碎动作不会各自生成一条汇报。
3. GUI 中阶段汇报位于其对应执行过程之前。
4. 私有思考不进入正文或数据库公开消息。
5. 简单任务可直接答复，不强制插入进度文字。
6. Harness、事件协议、数据库 schema、工具 schema 和 Prompt Ledger 保持不变。
7. 前端测试、构建、Agent 端到端测试以及提示词字节稳定性回归全部通过。

## 风险与边界

- 自然语言汇报由模型遵循提示词产生，频率不是协议级强制保证；本设计通过清晰规则约束，而不引入机械模板或合成兜底。
- 不同模型对“一至两行”的理解可能略有差异；验收以简短、关键阶段、非逐工具播报为准。
- 如果未来需要强制可观测的阶段状态，应单独设计结构化进度协议，不能在本次改动中隐式扩展工具或事件 schema。
