# 无边框标题栏拖动状态修复设计

## 背景

最新的无边框标题栏改动为避免 `SC_MOVE` 吞掉双击序列，在前端增加了 400ms 延迟和 4px 位移阈值。当前实现把所有 `MouseEvent.detail >= 2` 的按下都视为双击的第二次按下，因此双击还原后立即进行的第三次按下（`detail = 3`）也会被拒绝，窗口必须等待系统连击计数重置后才能再次拖动。

同一段逻辑还有两个生命周期缺口：鼠标松开时不会取消待执行拖动；位移提前触发原生拖动时只清空 timer 变量，没有取消实际的定时回调。

## 目标

- 双击标题栏继续通过 `window_native_maximize` 最大化或还原。
- 双击还原后，第三次按下并移动超过阈值时可以立即拖动。
- 鼠标已经松开后，待执行 timer 不得启动原生移动循环。
- 一次拖动结束后，不得留下能够干扰后续操作的 timer 或全局事件监听器。
- 保持现有 `window_begin_drag`、Aero Snap、窗口控制按钮及拖动区域上报行为不变。

## 非目标

- 不修改 Python、Win32 或 pywebview 桥实现。
- 不改变 400ms 双击判定窗口和 4px 位移阈值。
- 不重构整个 `Topbar.vue`，不抽取新的通用拖动框架。
- 不修改打包产物或版本号。

## 方案比较

### 方案 A：只把 `>= 2` 改为 `=== 2`

改动最少，能修复第三次按下被拒绝的问题，但仍保留 mouseup 后误触发和旧 timer 干扰后续操作的竞态，不满足完整验收标准。

### 方案 B：在 `Topbar.vue` 内补全待拖动生命周期（采用）

保留现有架构，在组件内统一管理 timer、mousemove、mouseup 和 armed 状态。奇数次按下可开始新拖动，偶数次按下交给双击处理；所有取消和执行路径都经过同一个清理函数。

该方案改动集中、容易审查，能够修复主问题和两个已确认竞态，不影响 Python 原生层。

### 方案 C：抽取独立 composable 或显式状态机模块

隔离性和复用性更强，但当前只有一个调用点，会增加文件、接口和测试层级。对本次小范围回归修复属于不必要扩张。

## 详细设计

### 状态与清理

`Topbar.vue` 继续维护一个待拖动状态，包含：

- 400ms timer 句柄；
- 是否已 armed；
- 当前 mousemove 和 mouseup 监听器的解除入口。

`cancelPendingDrag()` 必须幂等完成以下动作：

1. `clearTimeout` 并清空 timer 句柄；
2. 移除本次注册的 mousemove 和 mouseup 监听器；
3. 清空 armed 状态。

组件卸载和双击处理前也调用该函数，保证没有悬挂任务。

### 按下仲裁

`beginDrag(event)` 按以下规则处理：

- `detail` 为大于零的偶数时，表示连续点击序列中的第二次按下；取消待拖动并等待 `dblclick`，不进入移动循环。
- `detail` 为奇数时，包括首次按下和双击后的第三次按下；结束旧待拖动后，建立一轮新的待拖动状态。
- `detail = 0` 视为测试或合成事件的首次按下，保持现有兼容行为。

新一轮待拖动同时监听：

- mousemove：位移超过 4px 后立即进入原生移动循环；
- mouseup：鼠标已释放，取消本轮待拖动；
- timer：按住且未超过位移阈值满 400ms 后进入原生移动循环。

### 进入原生移动循环

进入 `window_begin_drag` 前先保存 armed 状态，再调用统一清理函数。只有保存的状态为真时才调用桥接口。这样可以确保 timer 和监听器在原生移动循环开始前已经全部失效，旧回调不能污染下一轮操作。

桥接口仍使用非等待调用，保持现有 GUI 线程和 Windows 模态移动循环语义。

### 错误处理

- pywebview 桥或可选方法不存在时保持静默无崩溃，与现有行为一致。
- 重复取消和组件卸载后的清理必须安全。
- 不增加降级路径；非法的悬挂状态通过测试直接暴露。

## 测试设计

在 `Topbar.test.ts` 使用 fake timers 和合成鼠标事件覆盖：

1. 首次按下后未立即调用，保持按住 400ms 后只调用一次 `window_begin_drag`。
2. 首次按下后在 400ms 内 mouseup，超过 400ms 仍不得调用。
3. `detail = 3` 的按下随后移动超过 4px，应立即调用一次，验证双击后可立即拖动。
4. 位移提前触发后启动下一轮按下，旧 timer 到期不得提前触发下一轮移动；新 timer 到期才允许触发。
5. 双击仍只调用 `window_native_maximize`，不调用 `window_begin_drag`。
6. 现有 Topbar 测试、前端完整测试和构建继续通过。

## 验收标准

- 自动化回归测试先在旧实现上失败，在新实现上通过。
- 双击最大化、双击还原、普通拖动、长按拖动、双击后立即拖动互不冲突。
- git diff 仅包含设计文档、`Topbar.vue` 和 `Topbar.test.ts`；若验证生成构建产物，不纳入提交。
