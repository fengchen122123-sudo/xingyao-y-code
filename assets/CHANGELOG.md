# Y-CODE 更新日志

## 1.3.5 (2026-10-01)

- 新增：内置「QQ2009」GUI 皮肤（设置 → 外观与主题）——致敬 2009 年 QQ 经典界面：浅蓝渐变标题栏、浅蓝面板、白底工作区与 QQ 蓝强调色，另带一层主题专属 CSS（`frontend/src/themes/qq2009.css`）还原渐变标题栏、橙色悬停等平色 token 表达不了的质感；侧栏配经典用户卡（昵称 / 个性签名 / 在线状态均可就地修改，点头像可换自定义头像、GIF 头像按帧播放，全部本地持久化）与会话搜索框，输入框上方补经典工具栏（图片 / 文件附件入口），用户消息显示昵称行，右面板置顶一张动态 QQ 秀
- 新增：内置「田野笔记 Field Notes」GUI 皮肤（设置 → 外观与主题）——纸质笔记本配色：墨绿框架（顶栏 / 左侧栏 / 状态栏）+ 米色纸面工作区 + 朱橙强调色，方正圆角与细边框
- 优化：内置主题引入「主题身份钩子」`data-gui-theme-id`——主题专属 CSS 以该属性为作用域，仅对应主题激活时生效；主题切换与预览回滚时同步还原该属性，避免候选主题的原生标题栏预览失败后旧主题被候选皮肤染色
- 修复：模型连续多步复读同一段短正文导致回合卡死——此前模型既不调工具也不给结论，只反复刷「好。」「嗯。」这类填充词或近似变体，前端气泡持续刷屏、状态栏长期停在「生成中」；现按正文指纹滑窗检测（连续 3 步无工具调用，且指纹逐位相同或两两相似度 ≥ 0.9），首次命中发提示并要求立即收敛，再次命中发错误并熔断收尾、返回已产出内容；指纹只取促升前的原始正文，思考内容不参与判定，避免误伤正常多步推理
- 修复：纯填充词（「好。」「嗯。」「OK。」等）此前被判为有效正文，使慢步熔断 / 总结催促 / 收尾报错三道护栏同时短路；现收紧判据——剥离噪声后按标点切分，每个片段都命中填充词词表且残余长度 ≤ 6 才判为空正文（宁可漏判，不误判正常短回复）
- 修复：额度耗尽 / 鉴权失败 / 权限受限 / 模型不存在等确定性上游失败此前仍会重试到底，反复空烧额度、拖长用户等待；现命中即 fail-fast 直接抛出，走既有失败收尾（429 等瞬时错误的退避口径不变）
- 修复：电脑操控进入用户接管态后，回合正常收尾时 run 既无终态也不释放排他租约，下一回合被 `computer_session_busy` 永久挡死——现放行 `waiting_for_user → completing` 转移，接管态与普通收尾一样终结并交还租约（保留浏览器会话，不关掉用户此刻正在手动操作的窗口）；右面板接管态文案同时给出交还指引「在对话里说一声，星瑶会重新接管继续」
- 修复：电脑操控收尾动作抛异常时无兜底释放，租约可能留活——现收尾失败一律强制 stop 释放（以 `cancel_owner=False` 跳过取消事件置位，避免把正常结束的回合误标成「已取消」），保证回合结束绝不留活租约
- 修复：电脑操控停止在途时再次 stop 会抛「stopping → stopping」并中断正在进行的清理链；现幂等返回当前快照，不重复释放与关闭 backend
- 优化：电脑操控占用错误带上被占 run 的当前状态，「下一回合拿不到租约」一眼可诊断，不必翻日志
- 优化：子代理面板任务描述默认收 5 行，鼠标悬停弹出浮层展示全文（自绘气泡，替代会把长段落拉成超长单行的原生 title）
- 优化：侧栏项目分组的删除改为弹窗二次确认（原为分组头内联的红色小按钮）
- 优化：内嵌浏览器自动化控件改用独立 profile 目录并校验 CDP 端点，避免与用户日常浏览器 profile 互相干扰

## 1.4.0 (2026-09-29)

- 新增：设置 → 飞书集成内置完整配置说明——飞书侧六步（建应用 / 开权限 / 事件订阅切长连接 / 发布版本 / 加入会话 / 取 open_id），并列出「连不上、收不到消息」的排查顺序；另附配置检查清单，一眼看出配到哪一步
- 修复：飞书新建会话的工作目录语义——`/new` 此前未显式指定目录，而后端 `create_session` 的默认是**星瑶进程当前目录**，导致飞书新建的会话被悄悄绑到项目目录上（观感是"工作目录莫名其妙"）；现改为显式创建**自由对话**（与桌面「新建对话」一致），并新增 `/newdir` 选择绑定项目目录；`/list` 每项补上工作目录，自由对话显示「自由对话（未绑定目录）」
- 新增：飞书 `/mode` 执行权限档位（变更前确认 / 自动编辑 / 计划 / 完全访问）——只绑定到飞书这个会话，桌面端全局默认不受影响；`/sandbox` 沙盒放行开关（全局项，卡片上明确标注影响范围）。两者都可在功能面板一键进入，**写入一律要求审批白名单内的人**（白名单为空时卡片不渲染按钮，与审批同一套 fail-closed 姿态）
- 新增：飞书 `/whoami` 指令——直接回你的 open_id 与 chat_id，解决「不知道自己的 open_id 填不进审批白名单」的问题（open_id 按应用区分，必须用星瑶看到的这个值）
- 新增：飞书通道——在飞书里和星瑶对话：发消息即驱动一轮任务，执行完成卡、权限审批卡、提问卡、待拍板收件箱、卡住提醒、功能面板与指令集（/help /whoami /panel /status /new /list /switch /model /agent /inbox /stop）全在飞书闭环
- 新增：飞书接入走官方「长连接」通道（企业自建应用主动连飞书），免公网 IP、免内网穿透、无需回调地址与校验密钥；连接代码自维护于 core/feishu/_lark_ws（搬运自 lark-oapi 1.7.3，MIT），不新增任何第三方依赖、不改动 websockets 等现有依赖版本
- 新增：设置 → 飞书集成——填写 App ID / App Secret / 审批白名单 / 固定推送会话，「测试连接」直接校验凭据；密钥加密落盘（Windows DPAPI）、界面与快照均不回显明文，留空表示不修改已有密钥
- 新增：飞书权限审批 fail-closed——未配置审批白名单时飞书侧不可审批（卡片只做提醒，仍需回桌面端处理）；白名单外的人点击会被拒绝且不回调后端
- 新增：飞书会话各自绑定星瑶会话（命名「飞书 · <open_id 前 8 位>」，绑定关系持久化），多群/多单聊互不串味；桌面端发起的回合不产生飞书消息，但桌面回合的审批与提问同样推送到飞书（人在外面也能拍板）
- 新增：飞书卡片 2.0 红线固化——无 note 标签（落款用 markdown）、按钮必须 behaviors callback、回调结果卡必须包 raw、input max_length ≤ 1000、资源超过 5 条折叠
- 优化：飞书通道默认关闭且开关一键生效；未配置时星瑶行为与升级前完全一致（不建连接、不做任何事）
- 优化：飞书完成卡上追问后不再把原卡片内容冲掉——飞书的卡片回调是「原地替换」语义，此前直接返回一张小回执卡会把星瑶的回复冲掉；现在保留原内容并在末尾追加一行「✅ 已发送」，反复追问也不会累积状态行
- 修复：飞书里发消息后收不到任何回复（回合其实已跑完，卡片静默不发）——星瑶会在回合中把会话自动重命名（首条消息当标题），而 `turn_finish` 事件带的是**改名后**的会话名，通道按旧名索引待发结果因而查不到；现已建立改名别名并把绑定关系随迁（顺带修掉「改名后下一条消息会另建会话、话题被重置」）
- 修复：飞书完成卡被飞书整卡拒收导致「消息发出去了但收不到回复」——卡片表单里输入框与提交按钮同名（都叫 reply），飞书报 230099/11310 `name(reply) duplicate`；已改名区分，并新增卡片结构红线测试（遍历全部卡片构造器校验无 note 标签、按钮 callback、input 长度上限、**同一表单内元素 name 唯一**）防同类问题
- 修复：飞书回合发起模型请求时报 `computer_turn_source 只允许受控值 local 或 lan`——回合来源在入口层与低层各有一份白名单，新增 `feishu` 时只改了入口层；现已统一（报错文案也改为列出全部受控值），并补一致性测试防同类漏改
- 优化：飞书配置说明补齐「卡片回调」这一块——`card.action.trigger` 需加在「事件与回调」的回调/卡片回调处，只配事件订阅时消息能收但卡片按钮点了没反应；另补入站诊断日志（事件到达/去重/消息与指令/发送结果），"连上了但收不到消息"可直接看日志定位
