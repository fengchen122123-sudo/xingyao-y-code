# Y-CODE 更新日志

## 1.2.13 (开发中)

### 新增

- 修复对话气泡「模型显示与实际调用不一致」问题（如界面显示 k3、实际调 deepseek）：根因是气泡统一显示全局"当前激活模型"（`activeModelName`），会话切过模型后历史消息全显示成新模型。现改为**每条助手消息记住生成时所用的模型**：落库时在 assistant 消息副本附加 `_display`（`model_id`/`model_name`，从厂商配置反查 litellm_model 对应显示名）显示元数据——仅写落库副本、不进入发给 LLM 的内存消息，从根上杜绝提示词污染；`_load_session_messages` 回放时透传 `model_id`/`model_name` 到前端，`ChatMessage` 接口新增对应字段，气泡优先显示本条消息自己的 `model_name`、旧消息缺省时回退当前激活模型。上下文/用量上限等合成提示消息同样绑定生成时模型
- 对话区新增「我的消息」红点导航轨道（对齐 Trae/Codex 体验）：对话区右侧固定一列小圆点，每条用户发送的消息对应一个点，点击平滑跳转到对应消息；点数随消息增加而增加，用户消息在任何形态下（含上下文压缩后）都完整渲染，轨道不丢点。轨道固定钉在对话区右缘、垂直居中，不随内容滚动——随时可点，不必跟着内容滚回去找
- 轨道点按当前阅读位置实时高亮：正在显示的那条消息对应点为深灰实心放大，其余为浅灰；点击某点立即高亮该点并钉住，直到用户手动滚动（滚轮/触摸）再交还给几何判定。判定分三层：点击钉住优先；已滚到底部时直接高亮最后一条（修复"停在底部看最新消息却高亮倒数第二个"的误判）；浏览历史中按视口中线判定当前消息
- 对话区滚动改为「跟随模式」智能滚动：停留在底部时新内容（流式 token、工具时间线、思考流）自动吸底；用户一旦向上滑动立即冻结位置，不再被生成过程强制拉回底部——此前 `currentStreamingText`/`messages.length` 等 watcher 无条件 `scrollToBottom()` 是"运行中无法向上翻看历史"的根因。上滑后右下角浮现「回到底部」悬浮按钮，点击或手动滑回底部即恢复跟随。发送新消息、切换会话、从设置页返回、权限询问四类场景仍强制回底并恢复跟随
- 滚动状态机抽为 `useChatScroll` 组合式函数（`frontend/src/composables/useChatScroll.ts`），同帧内普通滚动与强制滚动合并、force 升级覆盖不被吞；红点导航抽为 `MessageNavRail.vue` 组件，含滚动/触摸/ResizeObserver 监听与消息条数自适应

### 预置厂商与模型

- 预置厂商「深度求索」新增 `deepseek-v4-flash-vision-exp` 模型（100 万上下文、支持多模态），GUI 模型设置页与 CLI 模型选择均可直接选用；`config.example.json` 示例配置同步新增
- 新增命令解释器显式选择：`execute_command` 支持 `shell_id` 参数按次覆盖默认解释器（auto / cmd / powershell / pwsh / bash / zsh / sh），命令失败后可根据报错显式切换解释器语法重试；解释器不可用时明确报错，不做静默降级
- 新增 GUI「系统设置」页（设置 → 系统设置）：可视化查看本机已安装的命令解释器并切换默认解释器，不可用解释器禁用并说明原因；运行时上下文同步注入「默认命令解释器」提示，引导模型按所选解释器语法生成命令

### 修复

- 修复无边框窗口最大化遮挡任务栏/第二屏无法最大化/拖动失效：此前伪最大化方案（拦截 `SC_MAXIMIZE` 改 `SetWindowPos` 全屏）架构不成立——主屏 `rcWork` 不可靠且 WebView2 仍按全屏渲染导致遮任务栏，第二屏负坐标下 WinForms 坐标系错乱导致无法拖动与显示异常。现改为 Windows 官方支持的 `WM_GETMINMAXINFO` 处理：把最大尺寸/位置钳制到窗口所在显示器的工作区（`MonitorFromWindow` + `rcWork`，排除任务栏），最大化仍走系统原生路径，动画、任务栏交互、多显示器、DPI 全部系统接管；`window_toggle_maximize` 回归原生 `SC_MAXIMIZE`/`SC_RESTORE`，最大化状态以 `IsZoomed` 为权威来源
- 修复无边框标题栏双击最大化→还原后快速拖动失效并闪现禁用光标的问题：根因是标题栏拖拽区 HTCAPTION 命中拦截与前端 DOM 驱动的双轨冲突——实测全部交互（双击、拖动）均走 DOM 事件，原生 caption 路径从未承接，但拦截间歇生效会在手势中途把 mousemove/mouseup 重新路由为非客户区消息，DOM 事件流半途丢失、位移阈值路径失效，拖动退化为 400ms 定时器兜底；快速拖动在松手瞬间才进入 SC_MOVE（数毫秒即被终结）从而闪现禁用光标。现移除拖拽区 HTCAPTION/HTTRANSPARENT 命中拦截（边缘 resize 拦截保留），标题栏交互完全由前端 DOM 事件驱动（mousedown + 位移阈值即时进入原生移动循环，双击走 SC_MAXIMIZE/SC_RESTORE）；同时保留 GUI 线程内 GetAsyncKeyState(VK_LBUTTON) 权威状态守卫，左键已松开的过期拖动请求一律拒绝（返回 left_button_released），绝不进入无有效按键手势的 SC_MOVE
- 修复多显示器下窗口拖拽贴边/最大化误判：Aero Snap 贴边判定此前拿主屏宽度与原点直接比较光标坐标，第二屏（负坐标或超出主屏范围）中间松手会被误判为贴主屏边缘。现改用 `MonitorFromPoint` + `GetMonitorInfoW` 定位光标实际所在显示器、相对其边界判定；第二屏中间不再误触发，真实贴边（含第二屏边缘）仍正确生效
- 修复空会话切换推理强度/权限模式/沙盒开关导致欢迎页消失（表现为页面跳转）：空会话下不再插入通知消息，仅会话已有真实对话时才提示；调整失败时仍保留失败提示
- 修复 GUI 计划编排「计划项不存在」：8-19 引入的按会话路由计划注册表生效后，`plan_write`/`plan_update`/`plan_retry`/`plan_read` 四个工具函数仍在裸写进程级单例 `_DEFAULT_PLAN_MANAGER`，而 `run_subagent` 的调度器读的是会话专属管理器，导致 plan_read 能看到、run_subagent 却报「计划项不存在」。现四个函数全部改走 `get_default_plan_manager()` 线程路由，GUI 会话中计划读写与调度器读取一致
- 修复 `set_model` 切换模型时未按会话隔离的问题：`set_model` 新增 `sessionName` 参数，切换模型时精确绑定到目标会话，不再串扰其他会话的模型选择

## 1.2.12 (2026-08-24)

### 计划任务完成后自动清空

- 任务计划全部进入终态（completed / failed / blocked / cancelled）后，回合结束自动清空计划快照：GUI「计划」面板与 CLI 计划窗口归零，不再残留已完成或已终止的计划项；只要仍有 pending / in_progress 项（任务未完成）就绝不提前清空，跨回合任务的计划安全
- GUI 回合结束按会话显式路由精确清空，多会话并行互不串扰；清空时先向前端补发空计划快照（面板先归零）再发出回合结束事件（再解锁输入框）
- 清空调用带异常防护：即使计划落盘 IO 失败，回合结束事件也必然发出，输入框不会卡在锁定状态
- 防护早退回合的注册表污染：无激活模型、项目目录缺失等提前结束的回合不再以错误路径惰性创建计划管理器条目，避免该会话后续计划读写静默失效
- CLI 回合结束后计划面板同步重绘为「暂无计划步骤」
- 前端对计划事件载荷做防御性加固：`items` 非数组时静默忽略，不再因 TypeError 中断整条事件分发

### 执行中阶段汇报

- 系统提示词（CLI 与 GUI 同步）新增「执行中阶段汇报」规则：多步骤或预计超过约十秒的任务，在关键节点用一至两行正文向用户汇报「当前阶段或关键发现 + 下一步」——汇报开始处理、改变路径的关键事实、定位→修改→验证等阶段切换、长测试/构建的开始与结果；不逐个工具调用播报、不输出无信息的自我对话、不预告未经证实的成功，也不重复最终总结
- 助手消息的 Markdown 正文移到工具执行时间线上方：回合进行中的阶段汇报即时可见，不必等回合结束才出现在轨迹底部

### 无边框窗口 resize 方案重构

- 窗口四边/四角的拖拽调整大小改为「页面透明热区 + 原生系统 resize 循环」：WebView 内容铺满窗口、不再为了命中测试而缩进露出宿主边带，从根本上消除「浅色主题黑边 / 深色主题白边」问题

- 前端新增 8 个方向透明 resize 热区，桥接层新增 `window_begin_resize` 方法
