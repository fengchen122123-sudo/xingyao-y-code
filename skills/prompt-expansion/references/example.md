# 对照范例：一句话 → 复现级规格

> 用途：动笔前读一遍，学的是**密度与锐度**，不是段落标题。
> 下面的例子刻意选了参数密集、坑位真实的场景——因为只有这种场景才能看出"规格"和"复述"的差别。

---

## 原始输入（用户原话，只有 11 个字）

```
把手机拍的视频批量压小一点
```

## 平庸扩写（错误示范）

> 做一个视频压缩脚本，支持批量处理，用 ffmpeg 压缩，可以选择输出目录，要有进度提示，处理失败要提示用户。

问题：形态未定（脚本还是程序？）、参数全无（压到什么程度算"小"？）、边界未提（同名怎么办？竖拍视频？没装 ffmpeg？）、验收写成愿望。**这类文档执行出来每次都不一样，属于扩写失败。**

---

## 合格扩写（范例正文）

# 手机视频批量压缩 · 完整执行提示词
> 原始需求：把手机拍的视频批量压小一点

## 一、总提示词与交付形态

把指定目录下的手机视频批量压缩到约原体积 1/3，保持可接受的清晰度。

- **交付物**：单个 PowerShell 7 脚本 `compress-videos.ps1`，≤200 行，仅依赖系统已安装的 ffmpeg（要求 ≥6.0，脚本启动时校验版本）。
- **用法**：`.\compress-videos.ps1 -InputDir "D:\DCIM" -OutputDir "D:\out" [-Crf 23] [-Apply]`
- **默认 dry-run**：不加 `-Apply` 只扫描并打印待压缩清单与预估体积，不动任何文件。
- **输出**：原文件名 + `_c` 后缀（`IMG_2031_c.mp4`），与原文件同目录树结构；保留原文件不删。

## 二、技术规格

### 2.1 编码参数表

| 项 | 值 | 理由 |
|---|---|---|
| 视频编码 | libx264，`-preset medium` | 速度/体积平衡点，手机视频普遍短 |
| 质量 | `-crf 23` | 1080p 下体积约为原片 1/3，肉眼几乎无损；用户可调 18–28 |
| 分辨率上限 | `scale='min(1920,iw)':-2` | 只降不升；`-2` 保证宽高偶数，避免 yuv420p 报错 |
| 帧率上限 | `fps=fps='min(60,source_fps)'` | 不超采，不降帧 |
| 像素格式 | `-pix_fmt yuv420p` | 兼容播放器与网页 |
| 音频 | `-c:a aac -b:a 128k -ac 2` | 手机原声多为 128k 上下，不再提码率 |
| 元数据 | `-map_metadata 0` | 保留拍摄时间，方便相册排序 |
| 旋转 | `-map_metadata 0` 保留 rotate 标记，**不加** `-noautorotate` | 竖拍视频若不保留旋转会横着 |
| 容器 | `-movflags +faststart` | 边下边播 |
| 超时 | 单文件 30 分钟 | 防卡死；超时计失败 |

### 2.2 文件筛选

- 扩展名白名单：`.mp4 .mov .m4v .3gp .avi .mkv`（大小写不敏感，`-Filter` 逐项匹配）。
- 跳过：已带 `_c` 后缀的文件、隐藏文件、`OutputDir` 自身（防递归套娃）。
- 跳过体积 < 20MB 的文件（压了也没收益，写进日志说明跳过原因）。

### 2.3 幂等与冲突

- 目标文件已存在且大小 >0 → 跳过并在汇总里标 `SKIP(exists)`。
- 目标路径与源不同但同名文件已被别的源占用 → 追加 ` (1)`、` (2)`，最多试 20 次。
- 重复运行同一命令，第二次应全部 `SKIP`，不产生新文件。

### 2.4 执行与反馈

- 逐文件顺序处理，每完成一个打印：`[3/12] IMG_2031.mov  182MB → 61MB (33%)  耗时 42s`。
- 进度不依赖外部模块，用计数器实现；不使用 `Write-Progress`（在管道重定向时会污染输出）。
- 结束时打印汇总表：总数 / 成功 / 跳过 / 失败，失败列出文件名与 ffmpeg 最后 3 行错误。

### 2.5 安全红线

- 不删除、不覆盖任何原始文件；所有写入只发生在输出路径。
- `OutputDir` 与 `InputDir` 相同时直接报错退出（防自我覆盖）。
- 任何文件操作使用 `-LiteralPath`（中文、方括号、空格路径必须能过）。

## 三、边界与失败处理

| 场景 | 行为 |
|---|---|
| ffmpeg 未安装或版本 <6.0 | 启动即退出，打印安装指引与当前检测到的版本 |
| 输入目录不存在 / 无读取权限 | 退出码 2，中文报错说明具体路径 |
| 单个文件编码损坏 | 该文件计失败，继续下一个，删除半成品输出 |
| 输出盘空间不足 | ffmpeg 返回非 0，按失败处理并提示剩余空间 |
| 文件名含中文/方括号/空格 | `-LiteralPath` + 参数数组传参，不经字符串拼接 |
| 路径 >260 字符 | 加 `\\?\` 前缀重试一次，仍失败则记 `SKIP(longpath)` |
| Ctrl+C 中断 | 删除当前半成品输出，已完成的保留 |

## 四、验收清单

- [ ] `.\compress-videos.ps1 -InputDir "D:\DCIM"` → 不加 `-Apply` 时输出清单，`D:\out` 下无任何新文件。
- [ ] `-Apply` 跑完 → 每个 ≥20MB 的视频都生成 `_c.mp4`，原文件仍在。
- [ ] 取一个 1080p 竖拍视频 → 输出仍为竖向（不是横过来）。
- [ ] 同一命令再跑一次 → 全部 `SKIP(exists)`，无新增文件。
- [ ] 视频数 ≥3 时 → 进度行序号递增，末尾汇总数字与实际文件数一致。
- [ ] 把 ffmpeg 从 PATH 移除 → 启动立即报错并给安装指引。
- [ ] 用含中文和空格的目录名（如 `D:\我的 视频\`）→ 正常处理。
- [ ] 人为放入一个 0 字节的 .mp4 → 记失败，脚本继续处理后续文件。
- [ ] 压缩后抽样播放 2 个文件 → 画面正常、声音正常、时长一致。

- 未执行项须在交付说明里标 [未验证] 并写原因，不得默认视为通过。

## 五、假设清单

| 假设 | 若推翻需改动 |
|---|---|
| 目标压缩比约 1/3，CRF 固定 23 | 改 2.1 表的 crf 默认值与验收的体积比对阈值 |
| 保留原文件，不做删除 | 追加 `-DeleteSource` 开关与二次确认逻辑 |
| 不递归子目录 | 文件筛选一节加 `-Recurse` 参数与目录树映射规则 |
| 输出到独立目录而非原地 | 2.3 冲突规则与 2.5 红线需重写 |
| 单机顺序处理，不做并行 | 若要多线程，进度输出与失败汇总需改为线程安全结构 |
