# 质量评分标准（Quality Rubric）

10 项，每项 0/1/2 分，满分 20。**低于 16 分不许进入执行阶段**，任一项得 0 分必须修正后重评（0 分项通常是结构性缺失，不会因为总分够而可忽略）。

评分对象：落盘的 `<任务>/执行提示词.md`。自评与他评用同一把尺。

---

## 1. 交付物唯一确定（2 分）

- 2 分：文件数、路径、形态、体积上限、运行环境全部写死，读完不会产生"到底交付什么"的疑问。
- 1 分：形态清楚但缺体积/环境约束之一。
- 0 分：只写"做一个网页"这类形态描述，路径与边界全靠猜。

## 2. 技术选型唯一（G1）

- 2 分：每个依赖带精确版本号与安装/构建命令；无"或/建议/可以考虑/视情况"。
- 1 分：选型定了但版本或构建方式缺失。
- 0 分：出现并列方案让执行者自选。

## 3. 量化密度（G2）

- 2 分：平均每 100 字至少 1 个具体数值（尺寸/色值/时长/阈值/上限/版本号），且数值有单位。
- 1 分：量化集中在个别章节，其余章节仍是形容词。
- 0 分：通篇形容词，找不到可判定的数字。

> 检查：`spec_lint.py` 会算 `数字token / 中文字符` 比值，给出参考值。比值 < 1.0（每百字 1 个数）判 1 分，< 0.4 判 0。

## 4. 边界覆盖（G3）

- 2 分：空输入、超限、同名冲突、失败降级、无权限、离线六类逐条写了行为。
- 1 分：覆盖 3–5 类。
- 0 分：只写正常路径，或统一一句"做好异常处理"。

## 5. 交互矩阵完整

- 2 分：每个入口（键位/按钮/参数/触摸）都有一行对应行为，含移动端差异；无遗漏入口。
- 1 分：主入口齐了，次要入口或移动端缺。
- 0 分：列表式描述而非矩阵，无法判断是否遗漏。

## 6. 验收可勾选（G4）

- 2 分：每条验收 = 动作 + 期望观察 + 检查手段，能直接照做判定通过与否。
- 1 分：多数可勾选，个别是"运行正常"这类愿望。
- 0 分：验收是空话或干脆没有。

## 7. 假设显式（G5）

- 2 分：每条假设写明"我默认了什么 + 推翻后会改哪一段"。
- 1 分：列了假设但没写影响面。
- 0 分：没有假设清单，或把假设混在正文里当事实写。

## 8. 坑位预防

- 2 分：领域参数库里的坑位被有针对性地落到本文档（不是整段抄表，只挑与本案相关的），并给出规避做法。
- 1 分：提了一两句风险，无规避手段。
- 0 分：零风险说明，等执行时踩雷。

## 9. 未验证处理规则

- 2 分：明确"未执行的验证项如实标注，不得默认通过"，并说明标注格式。
- 1 分：口头提了一句，无格式约定。
- 0 分：没有这条，容易演变成假成功。

## 10. 可移植性（终局检验）

- 2 分：把文档给另一个执行者（或另一个模型），它不需要问任何问题就能做出等价产物。
- 1 分：能做出 70% 相似的东西，少数关键细节需追问。
- 0 分：离开原作者就做不出，说明规格没落纸。

## 评分表模板（写进文档末尾，交付时附上）

```
| # | 项目 | 得分 | 依据 |
|---|------|------|------|
| 1 | 交付物唯一确定 | /2 | |
| 2 | 技术选型唯一 | /2 | |
| 3 | 量化密度 | /2 | 数值 N 个 / 中文 M 字 = 比值 |
| 4 | 边界覆盖 | /2 | 覆盖 x/6 |
| 5 | 交互矩阵 | /2 | 入口 N 个，遗漏 0 |
| 6 | 验收可勾选 | /2 | 可勾选 N 条 |
| 7 | 假设显式 | /2 | 假设 N 条 |
| 8 | 坑位预防 | /2 | |
| 9 | 未验证规则 | /2 | |
| 10 | 可移植性 | /2 | |
| 合计 | | /20 | 门槛 16 |
```

## 常见虚高

- 数字堆在参数表里，正文却全是"合理""适当" → 第 3 项只能给 1 分，别给 2。
- 验收项写了 15 条但都是"功能正常" → 第 6 项 0 分，条数不等于质量。
- 假设清单把常识也列进去充数（如"使用 UTF-8"）→ 第 7 项降 1 分，假设应是真正需要用户拍板的分歧点。
