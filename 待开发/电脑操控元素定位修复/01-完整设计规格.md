## 1. 背景与目标

### 1.1 用户反馈

> 「我的操作经常会找不到要点击的位置，而 ZCode 找起来很准确。」

### 1.2 根因（已定位，有代码证据）

### 1.3 对照 ZCode

`packages/desktop/src/main/browserView/browserPlaywrightDomSnapshot.ts` —— 浏览器观察返回 **ARIA 文本树**：

```
- heading "登录" [level=1]
```

ZCode 还有一层清理逻辑（`normalizeSnapshotNode`）：
- 压平无语义容器（`generic` / `listitem` / `group`），保留其 children
- 移除无名称的 `img`（无法提供定位依据）
- 去掉内部 `[ref=...]` / `[cursor=...]` 标记

### 1.4 目标

- 浏览器 observe 产出**可交互元素列表**，走与桌面相同的 a11y-first 通路
- 新增浏览器的元素引用动作（`click_element` / `set_value_element`）
- 修复桌面 SoM 标注字体过小的问题
- 提示词强化，让模型优先用元素而非坐标
- **不破坏桌面路径、不破坏投影字节稳定性、不回归**

### 1.5 非目标

- **不做 iframe 穿透**（v1；ZCode 有专门的 iframe 预算与深度处理，列为二期）
- **不做 Shadow DOM 穿透**（v1；`querySelectorAll` 不穿透 shadow root）
- **不做跨页面 ref 持久化**（ref 是观察快照，页面变化即失效）
- **不改动坐标点击能力**（仍保留，作为回落路径）
- **不做桌面 UIA 覆盖扩展**（E5 列为 P3，见第 7 节）

### 2.2 元素收集脚本设计

注入 JS 提取可交互元素。核心逻辑：

```javascript
() => {
  const SEL = [
    'a[href]', 'button', 'input:not([type=hidden])', 'select', 'textarea',
    '[role="button"]', '[role="link"]', '[role="textbox"]', '[role="checkbox"]',
    '[role="radio"]', '[role="combobox"]', '[role="menuitem"]', '[role="tab"]',
    '[role="switch"]', '[role="searchbox"]', '[role="option"]',
    '[contenteditable="true"]', '[onclick]', '[tabindex]:not([tabindex="-1"])'
  ].join(',');

  const MAX_NAME = 80;
  const MAX_ELEMENTS = 200;

  // ---- 可见性判定 ----
  // 优先用 checkVisibility()（现代 Chromium 支持，含祖先隐藏判定）；
  // 不可用时回落到 getBoundingClientRect + computedStyle 组合判定。
  function isVisible(el) {
    if (typeof el.checkVisibility === 'function') {
      return el.checkVisibility({ checkOpacity: true, checkVisibilityCSS: true });
    }
    const rect = el.getBoundingClientRect();
    if (rect.width <= 0 || rect.height <= 0) return false;
    const style = getComputedStyle(el);
    return style.visibility !== 'hidden'
        && style.display !== 'none'
        && parseFloat(style.opacity) !== 0;
  }

  // ---- 视口内判定 ----
  function inViewport(rect) {
    return rect.bottom > 0
        && rect.right > 0
        && rect.top < window.innerHeight
        && rect.left < window.innerWidth;
  }

  // ---- kind 推导（HTML/ARIA 语义，见 2.3） ----
  function deriveKind(el) { /* ... 见 2.3 ... */ }

  // ---- name 推导（无障碍名称优先，见 2.4） ----
  function deriveName(el) { /* ... 见 2.4 ... */ }

  const out = [];
  let counter = 0;
  for (const el of document.querySelectorAll(SEL)) {   // 文档顺序，确定性
    if (counter >= MAX_ELEMENTS) break;
    const rect = el.getBoundingClientRect();
    if (!isVisible(el) || !inViewport(rect)) continue;
    counter += 1;
    out.push({
      ref: `el-${counter}`,
      kind: deriveKind(el),
      name: deriveName(el).slice(0, MAX_NAME),
      bounds: [
        Math.round(rect.left), Math.round(rect.top),
        Math.round(rect.right), Math.round(rect.bottom)
      ],
      enabled: !el.disabled && el.getAttribute('aria-disabled') !== 'true',
    });
  }
  return out;
}
```

### 2.3 kind 推导

**决策**：浏览器侧输出 **HTML/ARIA 原生语义**（`button` / `link` / `textbox` / `checkbox` ...），而不是映射到 UIA 的控件类型名（`Button` / `Hyperlink` / `Edit` ...）。

**理由**：
1. 模型对 HTML 语义更熟悉，认知负担更低；
2. 避免维护一张易漂移的映射表；
3. 两侧 kind 语义可类比（`button` ↔ `Button`），不造成理解障碍。

推导优先级：

```javascript
function deriveKind(el) {
  const role = el.getAttribute('role');
  if (role) return role;                       // ① 显式 ARIA role 优先
  const tag = el.tagName.toLowerCase();
  if (tag === 'input') {
    const type = (el.getAttribute('type') || 'text').toLowerCase();
    if (type === 'checkbox') return 'checkbox';
    if (type === 'radio') return 'radio';
    if (type === 'submit' || type === 'button' || type === 'reset') return 'button';
    if (type === 'search') return 'searchbox';
    return 'textbox';                          // text / password / email / number ...
  }
  if (tag === 'a') return 'link';              // ② 标签兜底
  if (tag === 'button') return 'button';
  if (tag === 'select') return 'combobox';
  if (tag === 'textarea') return 'textbox';
  return tag;                                  // ③ 其余用标签名
}
```

### 2.4 name 推导

按无障碍名称计算优先级（对齐 W3C AccName 规范的主流实现顺序）：

```javascript
function deriveName(el) {
  // ① aria-label
  const ariaLabel = el.getAttribute('aria-label');
  if (ariaLabel && ariaLabel.trim()) return ariaLabel.trim();

  // ② aria-labelledby 指向元素的文本
  const labelledBy = el.getAttribute('aria-labelledby');
  if (labelledBy) {
    const texts = labelledBy.split(/\s+/)
      .map(id => document.getElementById(id))
      .filter(Boolean)
      .map(node => (node.innerText || '').trim())
      .filter(Boolean);
    if (texts.length) return texts.join(' ');
  }

  // ③ 关联 <label>（仅表单控件）
  if (el.id) {
    const label = document.querySelector(`label[for="${CSS.escape(el.id)}"]`);
    if (label && label.innerText.trim()) return label.innerText.trim();
  }
  const wrappingLabel = el.closest('label');
  if (wrappingLabel && wrappingLabel.innerText.trim()) return wrappingLabel.innerText.trim();

  // ④ placeholder / title / alt
  const placeholder = el.getAttribute('placeholder');
  if (placeholder && placeholder.trim()) return placeholder.trim();
  const title = el.getAttribute('title');
  if (title && title.trim()) return title.trim();
  const alt = el.getAttribute('alt');
  if (alt && alt.trim()) return alt.trim();

  // ⑤ 可见文本（按钮/链接最常用）
  const text = (el.innerText || '').trim();
  if (text) return text;

  // ⑥ 兜底：空字符串（模型只能靠 kind 与 bounds 判断）
  return '';
}
```

### 2.5 隐私约束（硬性）

元素列表**只包含结构信息**，**绝不包含**：

- 表单的 `value`（用户已填的内容）
- `placeholder` 之外的输入控件内容
- Cookie / localStorage / sessionStorage
- 页面脚本变量

**注意**：`placeholder` 是设计上的提示文本，可收集；但 `input.value` **绝不收集**。

对齐 `browser_backend.py` 现有隐私铁律（模块 docstring 第 16 行附近：「不读 DOM 输入值、cookie、localStorage 或密码库」）。

### 2.6 数量与范围限制

| 限制 | 值 | 理由 |
|---|---|---|
| 最大元素数 | 200 | 对齐桌面 `MAX_ELEMENTS = 200`（`windows_elements.py:17`） |
| name 最大长度 | 80 字符 | 对齐桌面 `_MAX_NAME_CHARS = 80` |
| 收集范围 | **仅视口内** | 视口外元素模型看不到截图，也无法点击；滚动后重新观察即可 |
| 超限行为 | 截断到 200 | 与桌面一致 |

### 2.7 确定性保证

**必须满足**：同一页面状态、同一元素集合 → **逐字节相同**的输出。

实现要点：
1. `querySelectorAll` 返回**文档顺序**（稳定）；
2. ref 编号按遍历顺序递增（`el-1`, `el-2`, ...）；
3. **不使用**随机数、时间戳、`Math.random()`；
4. `getBoundingClientRect()` 的取整方式固定（`Math.round`）；
5. 元素列表的序列化顺序固定。

**校验方法**：连续两次 observe 同一未变化页面，`elements` 的序列化结果必须完全相同（见 03 验收清单 T-E1-6）。

## 3. E2 · 浏览器元素引用动作

### 3.1 白名单调整

`core/computer/actions.py:47`：

```python
# 改前
_DESKTOP_ONLY_KINDS = frozenset({
    "list_surfaces", "activate_surface", "invoke_surface", "observe_region",
    "list_elements", "click_element", "set_value_element",
})

# 改后
_DESKTOP_ONLY_KINDS = frozenset({
    "list_surfaces", "activate_surface", "invoke_surface", "observe_region",
    "list_elements",          # 仍为桌面专属：浏览器版由 observe 直接携带 elements
})
# click_element / set_value_element 改为双 target 支持
```

**设计决策**：浏览器**不提供独立的 `list_elements` 动作**。

**理由**：
1. 桌面的 `list_elements` 存在是因为「UIA 收集较慢、且需要独立刷新时机」；浏览器收集很快（一次 JS 求值），放进 observe 更自然；
2. 浏览器 observe 本来就返回截图，加上元素列表后**同一动作返回两种信息**——有 elements 时投影走文本路径，等于顺带完成了 `list_elements` 的职责；
3. **减少动作数量 = 减少模型往返**（这正是本次修复的目标之一）。

因此：
- 浏览器：`observe` → 自动携带 elements；`click_element` / `set_value_element` → 按 ref 操作
- 桌面：维持现状（`list_elements` 独立动作 + `click_element`）

### 3.2 元素 ref 的实现方式

**决策**：使用 **DOM 属性标记**（`data-ycode-ref`），而非「JS 侧索引定位」。

**方案对比**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A · 索引定位 | 每次按相同逻辑重新查询，用 ref 序号取第 N 个 | 不改页面 DOM | 两次查询间页面变化会导致索引漂移；失去 Playwright 的自动等待 |
| **B · 属性标记** ✓ | observe 时给元素打 `data-ycode-ref="el-3"`，动作时用 `page.locator('[data-ycode-ref="el-3"]')` | **Playwright locator 的自动等待、可点击性检查、滚动到视口全部白送** | 修改了页面 DOM（一个属性） |

**选择 B 的理由**：Playwright 的 `locator.click()` 会：
1. 自动等待元素出现与稳定
2. 自动滚动到视口内
3. 检查元素是否被遮挡、是否可点击
4. 失败时给出明确的原因

这些是**可靠性的大部分来源**——比手动算坐标点击强得多。

**属性名**：`data-ycode-ref`（带项目前缀，冲突风险极低）。

**清理**：不在页面卸载时主动清理（属性随页面生命周期结束自然消失）。

### 3.3 `click_element` 实现

在 `browser_backend.py` 的 `_dispatch_action` 中新增分支：

```python
def _cmd_click_element(self, page, element_ref: str) -> None:
    """按元素引用点击（浏览器）。ref 来自最近一次 observe 的 elements。"""
    self._require_ref_valid(page, element_ref)   # 见 3.5 有效性校验
    locator = page.locator(f'[data-ycode-ref="{element_ref}"]')
    try:
        locator.click(timeout=...)
    except Exception as error:
        raise ComputerControlError(
            "computer_element_unsupported",
            f"元素 {element_ref} 点击失败：{type(error).__name__}",
        ) from error
```

**错误码对齐**（沿用桌面已有语义，不发明新码）：
- ref 不在最近一次观察集合内 → `computer_element_stale`
- 元素存在但不可点击（被遮挡/禁用） → `computer_element_unsupported`

### 3.4 `set_value_element` 实现

```python
def _cmd_set_value_element(self, page, element_ref: str, text: str) -> None:
    self._require_ref_valid(page, element_ref)
    locator = page.locator(f'[data-ycode-ref="{element_ref}"]')
    try:
        locator.fill(text, timeout=...)
    except Exception:
        # 回落：部分富文本编辑器不支持 fill，改用聚焦 + 键盘输入
        locator.click()
        page.keyboard.type(text)
```

**为什么优先用 `fill()`**：
1. 直接设置值，**不经过输入法**（彻底绕开 IME 乱码问题）；
2. 比逐字符模拟键盘快得多；
3. 会自动触发 `input` / `change` 事件，页面框架（React/Vue）能正确响应。

**回落路径**的必要性：`contenteditable` 元素、部分富文本编辑器（如某些 Markdown 编辑器）不支持 `fill`，此时回落到「点击聚焦 + 键盘输入」。

### 3.5 ref 有效性校验

对齐桌面的 `WindowsElementLocator._require_ref_locked`（`windows_elements.py:106`）语义：

```python
def _require_ref_valid(self, page, element_ref: str) -> None:
    """ref 必须属于最近一次 observe 收集的元素集合。"""
    token = self._page_token(page)
    if token != self._observed_page_token:
        raise ComputerControlError(
            "computer_element_stale",
            "页面已切换，元素引用失效，请重新 observe",
        )
    if element_ref not in self._observed_element_refs:
        raise ComputerControlError(
            "computer_element_stale",
            f"元素引用 {element_ref} 已失效，请重新 observe",
        )
```

**需要新增的实例状态**：
- `self._observed_element_refs: frozenset[str]` —— 最近一次 observe 的 ref 全集
- 在 `_cmd_observe` 末尾更新
- 与 `_observed_page_token` 同生命周期

### 3.6 worker 协议兼容

浏览器可能运行在**独立 worker 进程**（`browser_worker.py`），observe 结果经 stdin/stdout JSON 往返。

**关键点**：`tuple` 经 JSON 往返后变成 `list`。父进程侧的反序列化必须归一化：

```python
# browser_backend.py 的 observe() 远程分支
observation = ComputerObservation(**response["observation"])
# elements 可能是 list（JSON 往返），归一化为 tuple
# 实施时确认 ComputerObservation 的 elements 字段类型注解与实际赋值一致
```

**验收要求**：worker 模式下 elements 能正确往返（见 03 清单 T-E1-8）。

## 4. E3 · SoM 标注字体修复

### 4.1 问题

`core/computer/som_annotator.py`：

```python
font = ImageFont.load_default()      # PIL 默认位图字体，约 11px
_RECT_WIDTH = 2                       # 固定 2px 红框
```

在 1920×1080 或更大的观察图上：
- 编号标签**小到难以辨认**——而模型正是靠它找位置；
- 2px 红框在复杂界面上**不显眼**。

### 4.2 修复

```python
def _load_label_font(pixel_size: int):
    """加载标注字体：优先 TrueType，失败回落 PIL 默认字体。

    确定性：字体文件与字号都由输入决定，不含环境探测分支之外的随机性。
    """
    for name in ("segoeui.ttf", "arial.ttf", "DejaVuSans.ttf"):
        try:
            return ImageFont.truetype(name, pixel_size)
        except OSError:
            continue
    return ImageFont.load_default()


def _label_metrics(width: int, height: int) -> tuple[int, int]:
    """按图片尺寸推导（字号, 框宽）。

    1920x1080 → 字号 24, 框宽 3
    3840x2160 → 字号 28（上限）, 框宽 4
    小图（如局部观察）→ 字号下限 14
    """
    base = min(width, height)
    font_size = max(14, min(28, base // 45))
    rect_width = max(2, min(5, base // 400))
    return font_size, rect_width
```

### 4.3 确定性保持

现有铁律（`som_annotator.py` docstring）：

> 无时间戳、无随机数、PIL PNG 编码参数固定（`optimize=False`），同一画面 + 同一元素集产生同一字节。

新实现必须维持：
- 字体选择**确定性**（固定候选列表 + 固定顺序，无环境探测的随机分支）；
- 字号由图片尺寸**纯函数**推导（同样的图 → 同样的字号）；
- **不引入**字体缓存导致的状态依赖。

**注意**：不同机器若安装了不同字体文件，标注字节可能不同。这对本地使用无影响（不跨机器比对），但需在文档中说明——**若未来要做跨机器 golden，需内置字体文件**。

```
     （输入框优先 set_value_element，中文不过输入法）；
   - 浏览器观察会自动附带页面可交互元素列表（el-N 编号），直接按列表操作，
     禁止凭截图目测坐标；
   - 只有元素列表为空（canvas 界面、图片型界面、自绘 UI）时，才退回截图坐标点击，
     并在回复中说明为什么元素不可用。
```

### 5.3 投影字节稳定性的影响

**分析**：
- `_GENERIC_DYNAMIC_PROMPT` 属于**动态块**（每轮可变的运行上下文），不在 `build_stable_prompt` 的稳定前缀内；
- `test_prompt_byte_stability.py` 的 golden 针对的是 `build_stable_prompt` / `build_stable_system_message` / 工具 schema——**动态块不在其中**；
- 但可能有其他测试断言该提示词文案（需实施时检查 `tests/test_computer_*.py`）。

**要求**：
1. 实施前先搜索是否有测试硬编码了该文案；
2. 若有，**按协议变更流程**同步更新基线并在提交信息中说明原因（这是有意的行为变更）；
3. **不得**为了通过测试而保留旧文案。

### 7.2 为什么列为 P3

3. 工作量大、收益不确定，且当前证据不足以判断优先级。

### 7.3 若要做，可探索的方向

- 扩大 control type 收集范围（含 `Pane` / `Text` / `Image`），配合可点击性过滤
- 引入 OCR 作为名称来源（当前 `name` 为空时模型无从判断）
- 应用专用插件（微信/浏览器等在 UIA 之外提供专用通道）

**本工作包不实施**，仅记录。

## 10. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 元素收集拖慢 observe | 中 | 收集限 200 元素；实施后测量 observe 耗时（基线 31ms，目标 <100ms） |
| 元素列表过长挤占上下文 | 中 | 限 200 元素 + name 限 80 字符；只收视口内 |
| `data-ycode-ref` 属性引起页面副作用 | 低 | 带项目前缀；仅属性不含行为；不监听不加事件 |
| 页面动态重绘导致 ref 漂移 | 中 | 由 `surface_generation` + page_token 校验拦截；过期即报错，不静默失败 |
| 富文本编辑器不兼容 `fill` | 中 | 回落键盘输入路径 |
| 单一页面元素超 200（长列表） | 中 | 截断 + 建议模型滚动后重新观察 |
| 投影文本路径导致模型看不到画面布局 | 低 | 这是**有意的**设计（对齐 ZCode「不同时给 snapshot 和 screenshot」）；元素列表丢失的是纯视觉信息，可用时模型可显式请求坐标路径 |
| 修改动态提示影响 golden | 低 | 实施前搜索确认；按协议变更流程处理 |
