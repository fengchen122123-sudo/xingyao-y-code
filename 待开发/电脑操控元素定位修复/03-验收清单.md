## 三、人工验收场景

> 复核注（2026-09-21）：以下场景需真实浏览器/桌面环境与人工操作，由用户在验收时执行。

### 场景 1：浏览器元素定位（核心场景）

1. 启动受管浏览器，打开一个含表单与按钮的页面（可用本地 loopback 测试页）。
2. 执行 `computer_action(kind="observe", target="browser")`。
3. **期望**：
   - 返回的是**元素列表文本**（`- el-1 button name='提交' bounds=(...) enabled=True` 形式），
     而**不是**截图；
   - 元素数量、kind、name 与实际页面相符。
4. 执行 `computer_action(kind="click_element", target="browser", element_ref="el-N")`。
5. **期望**：精确命中，页面产生预期变化。

### 场景 2：输入框填值（IME 免疫）

1. 页面上有一个文本输入框。
2. 执行 `set_value_element(element_ref="el-N", text="中文测试")`。
3. **期望**：输入框内容为「中文测试」，**无 IME 乱码**。

### 场景 3：CANVAS 页面回落

1. 打开一个纯 canvas 页面（如地图、绘图应用），或元素列表为空的页面。
2. 执行 observe。
3. **期望**：回落到 PNG 截图路径，模型能看到截图，**不报错**。

### 场景 4：ref 过期语义

1. observe 拿到 `el-3`。
2. 切换页面（或导航到新 URL）。
3. 执行 `click_element(element_ref="el-3")`。
4. **期望**：抛 `computer_element_stale`，提示重新 observe。

### 场景 5：SoM 标注清晰度（桌面）

1. 桌面场景执行 `list_elements`。
2. 查看返回的标注截图。
3. **期望**：编号清晰可辨（不再是 11px 小字），红框醒目。

### 场景 6：桌面路径零回归

1. 桌面场景执行 `list_elements` + `click_element`。
2. **期望**：行为与改动前**完全一致**。

### 场景 7：隐私检查

1. 页面中填写一个表单（用户名、密码）。
2. 执行 observe。
3. **期望**：元素列表中的 name 显示的是 placeholder 或 label（如「用户名」），
   **绝不显示已填的值**。

### 场景 8：效率对比（加分项）

1. 执行一个需要点击多步的任务（如「登录 → 进入某页面 → 点击某按钮」）。
2. 记录模型往返次数。
3. **期望**：相比改动前**显著减少**（不再有「点击落空重试」）。
