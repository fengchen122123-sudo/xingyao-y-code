# 星瑶 Git 管理验收清单

使用说明：每项记录“通过 / 不通过 / 不适用”，并附测试名、命令输出或人工证据。不得仅凭界面存在按钮判定通过。

## 1. 仓库与状态

- [ ] Git 未安装时显示明确错误，不导致星瑶启动失败。
- [ ] Git 低于 2.36.0 时工作台明确拒绝并给出升级指引，不调用旧命令模拟。
- [ ] 逐操作能力表与实际 Git 能力一致。
- [ ] 非 Git 目录正确显示 Init/Clone 入口。
- [ ] 工作区是仓库子目录时解析到真实根目录。
- [ ] 普通仓库、Worktree、Detached HEAD、Unborn Branch、Bare Repository 状态正确。
- [ ] 中文、空格和特殊字符路径状态正确。
- [ ] staged、unstaged、untracked、ignored、conflicted 数量正确。
- [ ] ahead/behind、upstream、stash 数量正确。
- [ ] Merge/Rebase/Cherry-pick/Revert 进行中状态正确。
- [ ] Rebase/Merge/Cherry-pick/Revert 可以与 conflicts 同时表示，不互相覆盖。
- [ ] 外部 Bisect/Am/未知 Sequencer 被识别为 unsupported external，而不是 Idle。
- [ ] 一个工作区存在多个已知仓库时能明确选择，不串状态。

## 2. 外部变化同步

- [ ] 在外部终端 `git switch` 后，GUI 状态栏和 Git 面板自动更新。
- [ ] 外部切换后文件树刷新为新分支内容。
- [ ] CLI 状态栏通过主线程安全刷新。
- [ ] 外部 Commit、Reset、Fetch、Stash 后状态正确更新。
- [ ] 外部操作制造冲突或 Rebase 状态后，星瑶显示对应状态和合法动作。
- [ ] 窗口失焦期间发生变化，重新聚焦后立即校准。
- [ ] 同一 Worktree 的多个会话同步更新。
- [ ] 其他 Worktree 不被错误刷新为当前分支。

## 3. 分支与 Worktree

- [ ] 清洁工作区能真实切换分支，磁盘文件随之改变。
- [ ] staged 内容存在时切换被拒绝。
- [ ] unstaged 内容存在时切换被拒绝。
- [ ] 仅有 untracked 文件时切换也被拒绝。
- [ ] 不发生自动 Stash、强制切换或修改迁移。
- [ ] 创建、重命名、安全删除和上游设置正确。
- [ ] Git 自身 Ref 校验拒绝非法分支名和选项注入。
- [ ] 被其他 Worktree 占用的分支不能在当前目录切换或删除。
- [ ] “在新工作区打开”创建真实 Worktree，并加入星瑶项目分组和会话。
- [ ] 不同 Worktree 能并行编辑、测试和执行允许并行的 Git 操作。
- [ ] 脏 Worktree 不能被普通移除。
- [ ] Worktree 移动/重命名、移除和 Prune 后状态一致。
- [ ] 首次创建 Worktree 要求选择默认根目录，不在仓库内部或沙盒外静默创建。
- [ ] 分支名经过安全编码后才用于建议目录，路径冲突明确失败且不自动追加随机后缀。

## 4. Diff、暂存与提交

- [ ] 工作区、暂存区和两个引用之间的 Diff 正确。
- [ ] 新增、修改、删除、重命名、复制、类型变化和执行位变化正确显示。
- [ ] 二进制文件不按文本 Diff 解析。
- [ ] 按文件 Stage/Unstage 正确。
- [ ] 按 Hunk/选中行 Stage/Unstage 正确。
- [ ] Patch 先 check；快照过期或上下文变化时拒绝。
- [ ] 大 Diff 截断或分页明确，不冻结 UI。
- [ ] Commit 只包含已暂存内容。
- [ ] 缺少 Git 用户名/邮箱时阻止提交并给出指引。
- [ ] Amend 和 Undo 最近一次本地提交符合选择的保留策略。
- [ ] 已配置签名时可签名提交，未配置时不伪造成功。

## 5. Remote 与同步

- [ ] Remote 增删改查正确，URL 凭据始终脱敏。
- [ ] Fetch、Fetch All、Prune 正确。
- [ ] Pull 默认只允许 Fast-forward。
- [ ] 分叉时明确要求 Merge 或 Rebase，不自动决定。
- [ ] Push 前显示 Remote、源/目标分支和提交范围。
- [ ] 首次发布分支正确设置上游。
- [ ] 不存在普通 `--force` 入口。
- [ ] `--force-with-lease` 有影响预览和高风险确认。
- [ ] 网络操作有进度、取消和超时，失败不自动重试。
- [ ] GUI 不会等待不可见的终端凭据输入。
- [ ] 删除远程分支/Tag 有二次确认。

## 6. Stash、历史与恢复

- [ ] Stash 创建、命名、包含未跟踪选项正确。
- [ ] Stash Diff、Apply、Pop、Drop 和从 Stash 建分支正确。
- [ ] Stash 冲突进入明确状态，不自动补救。
- [ ] 提交 DAG、分支/Remote/Tag 标记正确。
- [ ] 历史分页、筛选、提交详情和 Diff 正确。
- [ ] 文件历史跨重命名可追踪。
- [ ] Blame 正确显示提交、作者和行号。
- [ ] Reflog 能定位 Reset/Rebase/切换前位置。
- [ ] 能从 Reflog 创建恢复分支。
- [ ] 明确提示未提交文件的 Restore/Clean 不能靠 Reflog 恢复。

## 7. Merge、Rebase 与冲突

- [ ] Merge、FF、No-ff 正确。
- [ ] 普通 Rebase 正确。
- [ ] Interactive Rebase 支持 Pick/Reword/Squash/Fixup/Drop/Reorder。
- [ ] Cherry-pick 和 Revert 支持一个或多个提交。
- [ ] Continue、Skip、Abort 只在合法状态开放。
- [ ] 应用重启后能重新识别进行中操作，但不自动继续。
- [ ] 文本冲突可查看 Base/Current/Incoming/Result。
- [ ] Accept Current/Incoming/Both 与手工编辑结果正确。
- [ ] 二进制冲突可以明确选择一侧。
- [ ] 未全部解决时不能 Continue。
- [ ] AI 冲突建议不会未经用户确认自动覆盖文件。

## 8. 高风险操作

- [ ] Restore 和 Clean 显示准确影响范围并二次确认。
- [ ] Clean 使用 dry-run 结果作为确认清单。
- [ ] Hard Reset 显示丢失范围并要求输入分支名或 Hash。
- [ ] Drop Stash、强制删除未合并分支、远程删除和脏 Worktree 强制移除均有高风险确认。
- [ ] 删除当前分支或被 Worktree 占用分支被拒绝。
- [ ] Git 锁冲突直接失败，不自动删除锁文件。
- [ ] 不可逆操作不能伪称可被 `/undo` 或会话检查点恢复。

## 9. 并发与一致性

- [ ] 写操作按影响范围携带并校验 `worktree_version` 和/或 `refs_version`。
- [ ] 两类版本使用确定性 SHA-256 与规格定义的权威输入，不依赖 mtime 或文件正文全量哈希。
- [ ] 界面快照过期时拒绝操作并刷新。
- [ ] Worktree 锁和 Common Repository 锁顺序固定，无死锁。
- [ ] 长期后台服务存在时，只读、Stage/Commit、Ref-only 与 Worktree rewrite 按兼容矩阵分别处理。
- [ ] 未知前台变更命令存在时，冲突 Git 写操作被拒绝并显示活动任务。
- [ ] Git 工作区级操作进行中时，同一 Worktree 不启动冲突命令。
- [ ] 可识别的模型直接 Git 命令接入协调器。
- [ ] 外部进程竞态最终由快照/Git 锁显式失败，不误报成功。
- [ ] 不同 Worktree 的独立任务不被全局锁无故串行。

## 10. GUI

- [ ] 状态栏分支、脏状态、ahead/behind 和进行中操作正确。
- [ ] 分支入口、源代码管理面板、历史、冲突和 Worktree 页面可用。
- [ ] 文件/Hunk 操作后局部状态及时更新且最终与 Git 一致。
- [ ] 长任务不阻塞 GUI 主线程。
- [ ] Git 事件通过既有 GUI 队列，不从事件线程直接 `evaluate_js`。
- [ ] 桌面和窄屏布局无关键控件遮挡。
- [ ] 关键操作不依赖 Hover，图标有可访问名称，状态不只依赖颜色。
- [ ] 大仓库列表使用分页或虚拟化。

## 11. CLI

- [ ] 状态栏能显示 clean/dirty/ahead/behind/worktree/detached/冲突状态。
- [ ] `/git` 全屏管理器所有页签可操作。
- [ ] `/git` 子命令使用严格解析，不原样透传 Shell。
- [ ] 不存在 `/git -- <任意参数>`。
- [ ] 后台监控通过 prompt_toolkit 主循环刷新，不从后台线程直接操作 UI。
- [ ] 危险操作使用明确确认界面。
- [ ] `/help` 与补全菜单已更新。

## 12. 安全、隐私与回归

- [ ] Git 进程全部使用参数数组，不经过 Shell。
- [ ] 安全查询禁用可执行 fsmonitor、external diff 和 textconv。
- [ ] `ext` 和未知 Remote Helper 被拒绝；允许 Remote 协议符合白名单。
- [ ] Hooks、`core.hooksPath`、Filter、fsmonitor Hook、Credential Helper 和其他外部程序进入仓库信任流程。
- [ ] 安全相关 Git 配置或 Hook 变化后，原仓库信任失效。
- [ ] “允许本次”不跨任务持久化；持久信任文件原子写入且不包含凭据或 Hook 正文。
- [ ] 未信任仓库不能通过手动 Git 按钮执行外部程序。
- [ ] 路径参数正确使用 `--` 防选项注入。
- [ ] Remote、错误、日志和事件中没有 Token、密码或敏感 Header。
- [ ] 无自动重试、静默降级、模糊 Patch、自动冲突解决或后处理补救。
- [ ] 高风险操作先返回服务端预览，再使用绑定仓库、参数、快照和会话的一次性确认令牌执行。
- [ ] 过期、篡改、跨会话或重复使用的确认令牌全部被拒绝。
- [ ] 确认令牌超过 60 秒失效。
- [ ] 绕过前端弹窗直接调用 pywebview 桥不能执行高风险操作。
- [ ] Git 进程中断后重新读取真实状态，不伪称已自动回滚。
- [ ] 模型仍使用现有 `execute_command`，未新增重复 Git 工具。
- [ ] AI 辅助只发送用户可见模板消息，不隐藏修改 Prompt Ledger 或无提示上传 Diff。
- [ ] System Prompt、tools schema、Provider payload 和缓存稳定前缀未意外改变。
- [ ] 现有 `/worktree` 和 `core/worktree.py` 兼容测试通过。
- [ ] 多会话、工作区、命令权限、取消、文件树和 Diff 回归测试通过。
- [ ] Python 语法检查通过。
- [ ] 前端单元测试通过。
- [ ] 前端构建通过。
- [ ] 完整相关 Pytest 通过。
- [ ] README 和用户帮助文档更新。
- [ ] `待开发/星瑶Git管理/实施进度.md` 与实际完成范围和验证证据一致。

## 13. 最终完成定义

- [ ] 上述所有适用硬性项目通过。
- [ ] 没有 P0/P1 缺陷。
- [ ] 没有 TODO、占位实现、假数据或不可达按钮。
- [ ] 没有用“后续版本”推迟本规格内功能。
- [ ] 变更文件、测试结果、已知风险和实际使用的 Skill 已完整交付。
