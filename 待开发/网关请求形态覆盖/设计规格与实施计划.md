## 一、背景与问题证据

### 1.1 触发事件

2026-09-23 22:05，用户观察到状态栏缓存命中率降到 **83%**，怀疑是刚启用的阿里云 token-plan 渠道缓存没生效。

### 1.2 排查结论（实测，非推测）

用 GUI 真实库 `~/.ycode/ycode_gui.db` 按进程生命周期复算，**22:05:59 时刻的累计命中率为 83.18%**，与观察值一致。分解如下：

| 会话 | 渠道 / 模型 | 调用数 | 命中率 |
|---|---|---|---|
| 检查一下未提交的代码帮我 | 阿里云 token-plan / deepseek-v4.1-flash | 35 | 96.22% |
| 测试一下阿里云 的命中率 | 阿里云 token-plan / deepseek-v4.1-flash | 27 | 90.19%（热轮 96.20%） |
| **把星瑶的上文显示也改成z** | **tokenrhythm / deepseek-flash** | **5** | **60.54%** |
| keepalive 保活（阿里云） | — | 1 | 0%（0/49483） |

两条关键结论：

1. **83% 是口径问题，不是阿里云渠道故障**。状态栏 `main.py:get_status` 用的是**进程级累计** `cumulative_cached / cumulative_prompt`（`core/llm_diagnostics.py:_account_server_usage`），把本进程内所有会话、所有渠道、所有 scope 混算。阿里云渠道自身窗口内为 93.84%，会话内 `system_sha256` 全程单一值（无换代）。
2. **真正值得修的在 tokenrhythm 这条链路上**，共三个观测点：
   - 同一会话连续两次大请求（269540 / 282837 prompt）**每次只命中 10496**，第二次本该命中第一次的全部前缀；诊断表 `request_reason` 分别为 `first_generation` 与空（热路径）——即热路径整段 miss。
   - 保活请求 0/49483、本窗口 3 条保活合计 153357 prompt 只命中 51840（33.8%）。
   - 该会话整体 60.54%，是拉低进程累计的主因。

### 1.3 为什么这不是"tokenrhythm 没被适配"

2026-09-23 当天的 7 个 commit 已完成缓存判定**去渠道化**：`core/llm_dialects.py:is_deepseek_ledger_route` 的注释明确写着"只看模型家族，不看渠道：任意网关（tokenrhythm、阿里云 token-plan、其它中转）上的 deepseek 模型一律放行"。tokenrhythm 上的 deepseek 现在走的就是与官方完全相同的账本 + 工具字母序路径。

所以缺的不是"家族判定里的特例"，而是两样东西：

- **可调性**：网关侧行为（额外请求头、额外请求参数）目前没有任何配置入口，遇到网关亲和/分片类问题只能改代码；
- **可观测性**：诊断表只有 `messages_sha256 / system_sha256 / tools_sha256`，**请求头与 extra_body 完全不在指纹里**——一旦覆盖项害了缓存，事后无法归因（本次排查就吃了这个亏）。

## 二、目标与非目标

### 2.1 目标（用户已确认的能力边界）

**只做请求形态覆盖**：为指定渠道（首个使用者：`tokenrhythm.studio`）提供"额外请求头 + 额外请求体参数"的配置通道。不碰任何机制判定。

### 2.2 非目标（第一版明确不做）

- 不做账本 / 保活 / 工具排序 / 断点等**机制开关**的渠道化；
- 不做 UI 编辑入口（配置写在 `config.json` 里，改动即热生效）；
- 不做 `${env:VAR}` 之外的动态求值；
- 不改任何现有官方路由判定逻辑，不影响未配置渠道的请求字节（黄金测试守护）。

## 四、设计

### 4.1 配置落点：三方案（**待用户确认，开工第一件事**）

| 方案 | 形态 | 优点 | 代价 |
|---|---|---|---|
| **A. 顶层专用段** | `"tokenrhythm": {"headers": {...}, "body": {...}}` | 最贴合原始诉求，实现最小 | 第二个网关要照抄一遍，本质上又是一次渠道特判 |
| **B. 顶层通用覆盖层**（推荐） | `"route_request_overrides": [{"match": "tokenrhythm.studio", "headers": ..., "body": ...}]` | 复用 `cache_keepalive_routes` 的归一化匹配与指纹缓存脚手架，风格一致；阿里云/其它网关即刻可配 | 多一层抽象 |
| C. provider 级键 | 挂在 `providers[i].request_overrides` | 离设置页最近，用户可 UI 编辑 | 同一网关多个 provider 条目要重复配；要改 `_resolve_model_config` 合并逻辑 |

**推荐 B 的理由**：项目已有两套"按域名匹配的顶层 routes"，配套工具函数（`_normalize_route_match_key`、`_parse_route_match_entries`、`_remember_*` 指纹缓存）现成；B 的成本与 A 几乎相同，但不会变成一次性特判，与"可持续调优"的目标一致。

### 4.2 配置形态（以 B 为例）

```json
{
  "route_request_overrides": [
    {
      "match": "tokenrhythm.studio",
      "headers": {
        "X-TokenRhythm-Agent": "XingYaoCode/1.3.2"
      },
      "body": {
        "thinking": { "type": "enabled" }
      }
    }
  ]
}
```

- `match`：按 `_normalize_route_match_key` 归一化（完整 URL 或裸域名均可，取 host 比对，支持子串）；
- `headers` / `body`：均可省略；省略即该渠道不加任何覆盖；
- `body` 的语义是 **合并进请求体顶层**（等价于现在的 `extra_body` 通道），不是替换整个 body。

### 4.3 生效位置与 scope

- **唯一注入落点**：`_provider_request_options`（`core/llm_dialects.py:1589`）的返回值——headers 走返回里的 `extra_headers`、body 走 `extra_body`，由 `core/llm.py:1538` 的 `kwargs.update(...)` 汇入请求；native 透传白名单已含这两个键（`core/llm_native_transport.py:642`、`:1275`），`cache_benchmark.py:148` 也自动生效；
- **传输层零改动**：`core/llm_native_transport.py:581-583`（OpenAI 兼容）与 `:888-890`（Anthropic 协议）的合并顺序已经是"`tokenrhythm_agent_headers(url)` → `extra_headers`"，配置天然优先于硬编码的 `X-TokenRhythm-Agent`；dashscope 会话缓存头（`core/llm_dialects.py:1323-1325`）就是走这条通道的现成先例。**原方案改传输层两处组头点，已废弃**（变量名对不上真实作用域，且属重复造轮子，理由见 §5 Task 2）；
- **所有 cache_scope 统一生效**（`main` / `subagent:*` / `compression` / `keepalive` / `benchmark:main`）。
  理由：若只有 `main` 带头部覆盖，同一会话的保活请求形状不同，上游可能判成两条不同的亲和链——这正是本次观测到的保活 0 命中一类成因。

### 4.4 白名单与拒绝策略（硬约束）

**headers**：允许任意自定义头，但**禁止覆盖**下列键（命中即剔除该键并记 warning）：

```
authorization, content-type, accept, host, content-length
```

**body**：允许追加/覆盖"扩展语义"键，但**禁止**触碰请求语义核心键（命中即剔除该键并记 warning）：

```
model, messages, tools, tool_choice, stream, stream_options, max_tokens,
max_completion_tokens, api_key, api_base
```

拒绝策略是**键级剔除，不是整条丢弃**：一条配置里合法键照常生效，非法键被剥离并写入日志，请求一定照常发出（配置错误绝不阻塞对话）。

> ⚠ **已知语义连锁（2026-09-24 补）**：body 允许键里的 `thinking` 不是纯形态参数。`core/llm.py:1548` 用它判断是否下发 `tool_choice="auto"`——覆盖注入 `thinking.type="enabled"` 会让该请求不再带 `tool_choice`。这是项目有意为之的行为（开了深度思考就不强推工具调用），但请知悉：**覆盖 `thinking` 等于顺带改了工具调用行为**。只想调形态、不想动语义的，就别覆盖这个键。
>
> 另：覆盖的合并点落在一致性断言 `_assert_reasoning_request_consistent` **之后**（见 §5 Task 2），因此覆盖值不会触发该校验抛错——"配置错误绝不阻塞对话"这条硬约束得以保持。

### 4.5 身份纳入与可观测（本次排查的直接教训）

1. 覆盖生效后的**有效 headers 与有效 body 覆盖值**参与请求指纹，新增诊断字段：
   - `route_override_sha256`：`sha256(canonical_json({"headers": {...生效值...}, "body": {...生效值...}}))`，无覆盖时为空串；
2. 该字段随 `cache_request_diagnostics` 落库：建表 SQL（`core/memory.py:511-537`）加列 + 启动时 `ALTER TABLE ... ADD COLUMN` 迁移（写法参照 `core/memory.py:495-500` 的 token_usage 加列），插入语句在 `add_cache_request_diagnostic`（`core/memory.py:1204`）；
3. **落地链路**：`core/llm.py:1706` 调用 `_classify_cache_request_details(...)` 时传入 `resolve_route_override(model_name, api_base)["fingerprint"]`，逐层透传到 `_build_cache_request_diagnostic`（`core/llm_diagnostics.py:88`）的返回 dict；
4. **指纹不进 `_provider_request_options` 的返回值**：那是直接交给 litellm / native 的 kwargs，多塞一个自定义键会落进 native 的"未识别参数"告警（白名单见 `core/llm_native_transport.py:642`、`:1275`）；
5. 目标：任何一次换代，都能用 SQL 直接回答"是不是这条覆盖改的"。

### 4.6 安全

- 值支持 `${env:VAR}` 引用，密钥不落 `config.json`；
- 日志与诊断**只记键名与 sha256，从不记值**；`route_override_sha256` 是单向哈希，可安全入库；
- 不新增任何出网行为，不改变现有鉴权头来源。

### 4.7 错误处理

| 情形 | 行为 |
|---|---|
| `route_request_overrides` 不是列表 | 整项忽略，日志 warning |
| 某条缺 `match` | 该条忽略，其余照常 |
| `headers` / `body` 不是对象 | 该字段忽略，另一字段照常 |
| 命中白名单禁键 | 剔除该键，warning |
| 配置文件损坏 | 复用现有 `load_config` 的 `.bak` 恢复路径，本功能不做额外兜底 |

### 4.8 缓存与热更新

复用 `_qwen_cache_config_stamp()`（`core/llm_dialects.py:201`）的指纹缓存策略：条目格式 `(过期时间, stamp, entries)`——格式先例见 `_keepalive_routes_cfg_cache`（`core/llm_dialects.py:178`），再叠加 10 秒 TTL 兜底。用户改了 `config.json`，最迟 10 秒内生效，且不增加每轮读盘开销。

> **实施要点（这里有坑，2026-09-24 实测确认）**：只做 TTL、不做 stamp 的版本会让单测互相串味——测试用 monkeypatch 替换 `_load_config_for_overrides` 时，配置文件 mtime 与 loader 身份都不变，stamp 也就没变，10 秒内第二次调用仍返回上一组配置（实测：文档原先给的 5 个示例用例挂了 3 个）。因此：① 实现必须带 stamp；② 测试文件加 autouse fixture 把 `_cache["entry"]` 置 None（与 `_keepalive_routes_cfg_cache` 注释里写明的"测试可直接把 entry 置 None 强制重读配置"同一手法）。

```python
# core/route_overrides.py
"""渠道请求形态覆盖：按域名给指定渠道追加请求头与请求体参数。

设计约束（见 待开发/网关请求形态覆盖/设计规格与实施计划.md §4）：
- 只做形态覆盖，不参与任何缓存机制判定；
- 白名单拒绝策略为键级剔除，请求必定照常发出；
- 生效值参与指纹（route_override_sha256），便于事后归因。
"""
from __future__ import annotations

import hashlib
import json
import os
import re
import time

from core.llm_dialects import _normalize_route_match_key

CONFIG_KEY = "route_request_overrides"
HEADER_DENY_KEYS = frozenset({
    "authorization", "content-type", "accept", "host", "content-length",
})
BODY_DENY_KEYS = frozenset({
    "model", "messages", "tools", "tool_choice", "stream", "stream_options",
    "max_tokens", "max_completion_tokens", "api_key", "api_base",
})
_ENV_REF = re.compile(r"^\$\{env:([A-Za-z_][A-Za-z0-9_]*)\}$")
_TTL_SECONDS = 10.0
# 条目格式与 _keepalive_routes_cfg_cache 一致：(过期时间, stamp, entries)。
# 测试可直接把 entry 置 None 强制重读配置。
_cache = {"entry": None}


def _load_config_for_overrides():
    from core.model_manager import load_config
    return load_config()


def _config_stamp():
    """配置来源指纹（loader 身份 + config 文件 mtime），口径同 _qwen_cache_config_stamp。

    拿不到时返回 None：此时 stamp 恒等，只能靠 TTL 兜底（宁可不缓存，也不给出过期结论）。
    """
    try:
        from core.llm_dialects import _qwen_cache_config_stamp
        return _qwen_cache_config_stamp()
    except Exception:
        return None


def _expand(value):
    if isinstance(value, str):
        match = _ENV_REF.match(value.strip())
        if match:
            return os.environ.get(match.group(1), "")
    return value


def parse_route_request_overrides(data):
    raw = data.get(CONFIG_KEY) if isinstance(data, dict) else None
    if not isinstance(raw, (list, tuple)):
        return ()
    entries = []
    for item in raw:
        if not isinstance(item, dict):
            continue
        match = _normalize_route_match_key(item.get("match"))
        if not match:
            continue
        headers = item.get("headers")
        body = item.get("body")
        entries.append((
            match,
            headers if isinstance(headers, dict) else {},
            body if isinstance(body, dict) else {},
        ))
    return tuple(entries)


def _filter(headers, body):
    clean_headers = {
        k: _expand(v) for k, v in headers.items()
        if str(k).lower() not in HEADER_DENY_KEYS
    }
    clean_body = {k: v for k, v in body.items() if str(k) not in BODY_DENY_KEYS}
    return clean_headers, clean_body


def _cached_entries():
    """按配置指纹取解析结果：stamp 变化立即失效，10 秒 TTL 兜底。"""
    stamp = _config_stamp()
    now = time.monotonic()
    entry = _cache.get("entry")
    if entry:
        expires, cached_stamp, entries = entry
        if cached_stamp == stamp and expires > now:
            return entries
    try:
        entries = parse_route_request_overrides(_load_config_for_overrides())
    except Exception:
        entries = ()
    _cache["entry"] = (now + _TTL_SECONDS, stamp, entries)
    return entries


def resolve_route_override(model_name, api_base):
    """返回该渠道生效的覆盖项；无匹配时三项均为空（零影响）。

    model_name 目前不参与匹配（按域名匹配即可），保留形参只为与
    _provider_request_options 的调用形状对齐，并为将来"按模型细分覆盖"留口子。
    """
    empty = {"headers": {}, "body": {}, "fingerprint": ""}
    host = _normalize_route_match_key(api_base)
    for match, headers, body in _cached_entries():
        if not host or not match:
            continue
        if host == match or match in host:
            clean_headers, clean_body = _filter(headers, body)
            if not clean_headers and not clean_body:
                return empty
            payload = json.dumps(
                {"headers": clean_headers, "body": clean_body},
                ensure_ascii=False, sort_keys=True, separators=(",", ":"),
            )
            return {
                "headers": clean_headers,
                "body": clean_body,
                "fingerprint": hashlib.sha256(payload.encode("utf-8")).hexdigest(),
            }
    return empty
```

```python
def _apply_route_request_overrides(result, model_name, api_base):
    """合并渠道请求形态覆盖；无配置时原样返回（零影响）。

    必须在 _assert_reasoning_request_consistent 之后调用：覆盖值不参与一致性
    校验，配置错误才不会抛错阻断对话（§4.4 / §4.7 的硬约束）。
    """
    from core.route_overrides import resolve_route_override  # 局部导入，避免模块循环依赖

    override = resolve_route_override(model_name, api_base)
    headers = override.get("headers") or {}
    body = override.get("body") or {}
    if headers:
        merged = dict(result.get("extra_headers") or {})
        merged.update(headers)
        result["extra_headers"] = merged
    if body:
        merged = dict(result.get("extra_body") or {})
        merged.update(body)
        result["extra_body"] = merged
    return result
```
