## 一、ZCode 调研结论（它的 token 统计是怎么做的）

ZCode 是 React/TS 多包 monorepo（Electron 桌面 + Web + 终端 TUI，三端共享 `packages/ui`）。
与星瑶"输入框 token 展示"职能对应的是 **输入框工具栏的上下文用量组件**：

| 层 | 文件 | 职责 |
|---|---|---|
| 应用组件 | `packages/ui/src/chat-input-toolbar/contextUsage.tsx` | 触发器 + 悬停面板 + Coding/Start Plan 段 |
| 展示组件 | `packages/ui/src/components/ai-elements/context.tsx` | Context / ContextTrigger / ContextContent（改自 vercel/ai-elements） |
| 数据契约 | `packages/shared` 的 `taskUsage` | `{ used, size, cache?: { hitRate }, breakdown?: [{ source, chars }] }` |

**触发器**：14px 圆环图标（24 viewBox / r=10 / strokeWidth 4 / 背景圆 25% 透明 + 前景弧 70% 透明、
圆头线帽、-90° 起笔），默认色跟随弱化文字色。

**悬停面板**（HoverCard，320px 宽、圆角-xl）：

1. 标题行：`上下文容量` + 右侧等宽字体 `已用/总量 (百分比)`；
2. 进度条（高 8px；可按来源分段着色——同一色相五档深浅）；
3. **来源占比列表**：色块 + 名称 + 百分比（等宽、tabular-nums）。来源 7 类：
   对话消息 / 系统提示词 / 运行上下文 / 技能 / 工具提示词 / 系统工具 schema / MCP 工具 schema；
   口径为**字符数估算**（源码注释明确："用于 UI 展示比例，不作为 token 账本"）；
4. 缓存命中率行（分隔线 + 仅 ≥78% 时显示）；
5. Coding Plan / Start Plan 配额段——z.ai 订阅体系专属，星瑶无对应。

**交互**：openDelay / closeDelay = 0 的纯 hover；触摸设备 pointerdown 打开；Esc / 外部点击关闭。

## 二、星瑶现状与差距

**现状**（截至 2026-09-22）：

- `frontend/src/components/InputArea.vue`：输入框右侧 `ctx-ring` 圆环（18px SVG / viewBox 20 / r=8 /
  stroke 2.5 / -90° 起笔），弧长 = used/window；颜色 accent 且 >70% 变橙、>90% 变红（功能色）；
  悬停仅原生 `title` 文本（`ctxTooltip`）。
- 数据面（`gui_bridge.py:6162 get_token_usage`）：`used / window / cached_pct / cache_latest_pct /
  cache_hot_pct / cache_session_pct / cache_available / cache_hot_turns / cache_invalidation_reason /
  cumulative / prompt_tokens / cached_tokens / total_prompt / total_completion / total_cached`；
  **无来源占比**。
- 格式化约定：完整千分位数字（`frontend/src/utils/tokenFormat.ts`，明确不使用 K/M 缩写）。

**差距**：ZCode 的悬停详情面板（用量摘要 + 进度条 + 来源占比 + 缓存命中率）在星瑶缺失；
星瑶只有一行原生 tooltip。

## 三、设计

### 3.1 触发器（圆环保留，交互升级）

- 圆环本体与颜色逻辑（accent / 橙 / 红三档）保留；不改尺寸与线宽。
- 移除原生 `title`，改为 **hover 即弹出详情面板**（移入打开、移出延迟关闭）；挂到 `cursor` 指示。
- 触摸设备：点按打开/关闭。
- 打开时若鼠标从圆环移入面板，面板保持；离开面板后延迟关闭。

### 3.2 悬停详情面板（新增组件，结构照 ZCode、视觉用星瑶主题变量）

```
上下文容量                    12,345 / 128,000（9.6%）
▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░    ← 进度条，按来源分段着色（同色系深浅）
■ 对话历史        62%
■ 系统提示词      18%
■ 技能            12%
■ 运行上下文       8%
■ 工具定义         0%（有值才显示该行）
──────────────────────────────
缓存命中率        91.2%
```

- 定位：向上弹出（输入框在底部）、水平对齐锚点并 clamp 视口；`Teleport to body`
  （参照 `ModelCascader.vue` 的既有模式，避免层叠上下文遮挡）。
- 进度条颜色与分段色：由主题变量派生同色系深浅（对齐 ZCode 观感）；列表色块与分段同色。
- 数字格式：沿用星瑶约定（完整千分位；百分比 1 位小数），**不**采用 ZCode 的 K/M 紧凑格式。
- 空态：无 breakdown 时仅显示标题/摘要/进度条/命中率；命中率无值（`cache_available=false`）时隐藏该行。

### 3.3 来源占比：后端纯旁路统计（新增）

统计口径同 ZCode——**字符数估算，仅用于展示比例，不进 token 账本**；失败绝不影响对话主流程
（全部统计用 try/except 包裹，统计结果与请求内容零耦合）。

| 来源 | 统计方式 | 统计点 |
|---|---|---|
| 对话历史 | 组装后 history 各消息的字符量之和 | `core/agent_service.py:764 prepare_turn_messages` 组装完成处 |
| 系统提示词 | `build_stable_system_message` 输出字符量 − 技能段字符量 | 同上 |
| 技能 | 技能目录段字符量（`get_active_skills_catalog()`） | 同上 |
| 运行上下文 | 动态块 + 时间注记 + 后台汇总 + 引用块字符量 | 同上（组装收尾处各变量仍在作用域） |
| 工具定义 | `request_tools` 的 JSON 序列化字符量 | `core/llm.py:1375 request_tools` 组装处 |

存储：会话级快照（与 token 记账同锁写入，如 `session_token_usage["latest_breakdown"]`）；
输出：`gui_bridge.get_token_usage` 增加 `context_breakdown: [{source, chars}, ...]` 字段；
重算：`_recalc_token_usage` / 清空历史时同步清理（避免旧会话残留）。

### 3.4 数据流

```
组装完成 → 旁路统计（core）→ 会话级快照（同锁）
        → gui_bridge.get_token_usage（+context_breakdown）
        → token_usage 事件推送 → appStore.tokenUsage
        → InputArea ctx-ring → ContextUsagePanel（悬停渲染）
```

### 3.5 不移植 / 本次不动项

- **不移植**：Coding Plan / Start Plan 配额段（星瑶无订阅体系）；K/M 缩写格式（见上）。
- **不动**：输入框下方 `token-summary` 摘要行、App 顶栏 `Token %`、设置页"Token 统计"大屏、
  CLI 任何输出。

## 五、验证

- 后端：统计函数单测（含"统计失败不影响主流程"的旁路断言）；相关面回归
  （token 记账、`test_prompt_byte_stability.py` 必须保持不变）。
  Windows 命令：`venv\Scripts\python -m pytest <路径> -v`
- 前端：`npx vitest run`（面板组件 + InputArea + store 相关）；构建通过。
- 手工：GUI 中悬停圆环 → 面板出现、数据正确；发几轮消息后占比与命中率刷新。

## 六、约束与红线

1. **纯旁路**：统计失败绝不影响对话主流程；不改变任何发送给 provider 的字节。
2. 字节稳定：`build_stable_prompt` 等既有输出不得变化（本项不触碰相关逻辑）。
3. 双端：统计在 core 层，CLI 不消费也不受影响；前端改造仅 GUI。
4. 不引入第三方依赖。
5. 只在 `dev` 分支操作；不混杂无关重构。
6. 数字格式沿用星瑶现有约定（完整千分位）。
7. 验证纪律：不得把未执行或环境受限的验证写成通过。
