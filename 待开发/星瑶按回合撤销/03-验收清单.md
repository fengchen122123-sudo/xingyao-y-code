# 星瑶按回合撤销验收清单

本清单是功能完成定义。每个勾选项必须具有实际代码、自动化测试输出或人工验收证据。不适用项必须写明原因，不得直接跳过。

## 1. 分支、范围与计划

- [ ] 开发和提交在 `dev` 分支进行，未擅自合并到 `master` 或其他分支。
- [ ] 用户的无关已有修改被完整保留。
- [ ] 存在持久化实施计划和进度记录，且与实际代码一致。
- [ ] 实施覆盖完整规格，没有 MVP、占位按钮、TODO 或假数据代替必需功能。
- [ ] 变更集中在按回合撤销，没有无关大规模重构。

## 2. 架构与单一事实源

- [ ] 存在职责清晰的 `core/turn_undo/` 模块边界。
- [ ] GUI、CLI 和自然语言入口共用同一 `TurnUndoService`。
- [ ] `gui_bridge.py` 只提供窄的结构化桥接，没有复制文件恢复逻辑。
- [ ] `main.py` 只处理 CLI 解析、确认和渲染，没有第二套事务实现。
- [ ] 所有撤销操作由现有 `sessions.id` 不可变主键 + 全局唯一 `turn_id` 精确定位，没有全局“最近文件”或前端数组下标语义。
- [ ] 新 `turn_id` 使用完整 128 位随机 UUID 生成并作为不透明身份，旧带会话前缀值仅兼容读取。
- [ ] 数据库对新协议 `turn_id` 施加全局唯一约束，事件和 DTO 示例不再生成带会话名前缀的新 ID。
- [ ] 会话改名后仍能撤销原回合，新协议不从 `turn_id` 前缀推导会话名。
- [ ] 页面刷新和应用重启后，GUI 通过 `message_turn_links` 重建相同回合卡片，不仅依赖 Pinia 或实时事件。
- [ ] GUI/CLI 在首条用户消息和 `turn_start` 之前已确保 session、生成完整 `turn_id` 并创建 checkpoint；创建失败时不发出无归属事件。
- [ ] GUI 回合元数据不进入 Provider 消息正文或改变历史请求字节。
- [ ] 文件实际状态来自磁盘检查，不从 GUI 显示状态反推。

## 3. 数据库与状态模型

- [ ] 检查点、文件记录、撤销操作、操作文件、确认令牌和记忆纠正有持久化数据模型。
- [ ] `message_turn_links` 使用 `messages.id -> checkpoint_id` 规范化持久化消息回合关联，由检查点取得权威 `sessions.id + turn_id`，不复制消息正文或重复身份字段。
- [ ] 消息正文与 `message_turn_links` 在同一个 SQLite 事务中提交或回滚。
- [ ] Harness 的消息/事件原子提交路径同时写关联；非 Harness 用户消息路径显式携带 checkpoint，任何路径都不按时间范围事后回填。
- [ ] 零受控文件修改回合进入 `no_changes` 正常终态，不生成空撤销卡片。
- [ ] 数据库迁移幂等，新建和旧数据库都有测试。
- [ ] 所有 SQLite 写入函数明确 `commit()`。
- [ ] 非法状态迁移、未知枚举和未知 `schema_version` 显式失败。
- [ ] 撤销生命周期与 `SnapshotAvailability` 分字段持久化，快照过期不覆盖 `reverted` 审计事实。
- [ ] 检查点存在递增 `record_version`，影响确认范围的更新都会递增，执行以 compare-and-swap 校验版本。
- [ ] 文件 I/O 期间不长时间持有 SQLite 连接锁。
- [ ] 每个文件的操作进度独立持久化，不仅保存一个完成计数。
- [ ] 操作状态区分 `previewed`、`preparing` 和 `prepared`；权限拒绝/令牌过期在未写文件时进入 `cancelled`，不会被误标为中断事务。

## 4. 快照仓库

- [ ] 文件原始内容按字节保存，支持空文件、非 UTF-8 和二进制文件。
- [ ] 大文件使用流式读写和 SHA-256，不整体载入内存。
- [ ] 快照先写临时文件、刷新、校验，然后原子命名。
- [ ] 相同内容去重存储，数据库引用计数或反向引用可验证。
- [ ] 快照目录仅当前用户可访问，不通过 Bridge 暴露原始绝对路径。
- [ ] 快照缺失或哈希损坏使检查点不可用，不猜测修复。
- [ ] 配额不足时文件修改本身失败，不降级为不可撤销修改。
- [ ] GC 不删除中断、待恢复或仍被引用的快照。
- [ ] 保留数量和过期语义对 GUI/CLI 可见。

## 5. FileMutationRecorder

- [ ] 回合开始时持久化检查点，回合结束时封闭。
- [ ] 同步前台子代理显式绑定父回合检查点，不影响无关会话。
- [ ] 可能迟于父回合结束的后台写文件任务从启动时创建独立检查点和 `turn_id`，并用 `parent_checkpoint_id` 关联来源回合。
- [ ] 迟到任务不能取得已封闭检查点的新句柄，且在真正触盘前失败。
- [ ] 文件修改前先完成快照和数据库记录，失败时目标文件不变。
- [ ] 同一文件一轮多次修改保留最初 `before` 状态。
- [ ] 受控工具在写入前提供完整 `PlannedPathMutation`，记录器先持久化计划 `after` 节点、大小、SHA-256 和 blob 引用再允许写入。
- [ ] 每次写入后立即验证实际 `after` 与计划完全一致，不一致时不声称工具成功。
- [ ] 同一文件一轮多次修改用最新计划替换最终 `after` 引用，不覆盖最初 `before`。
- [ ] 修改后记录失败不会被工具声称为可撤销成功。
- [ ] 写入、编辑、删除、移动、重命名、复制覆盖和补丁工具全部接入。
- [ ] 可撤销工具注册元数据与记录器接入不一致时有校验失败。

## 6. 文件类型和路径

- [ ] 支持普通文件的修改、新建、删除和重命名。
- [ ] 严格可撤销节点仅限不存在路径和普通文件；目录、设备文件、管道、最终路径符号链接和硬链接在写入前明确拒绝。
- [ ] 恢复范围对内容字节、存在性和基本权限位有准确语义，不误称可恢复时间戳、Windows ACL、扩展属性或备用数据流。
- [ ] 重命名通过旧、新两个路径的明确状态恢复，不使用名称相似性推断。
- [ ] 大小写折叠、相对路径、路径穿越和符号链接切换有测试。
- [ ] 工作区外历史授权文件只能恢复原规范化路径。
- [ ] 前端或模型伪造文件路径无法扩大恢复范围。

## 7. 通用命令副作用

- [ ] 通用终端命令不通过文本解析、监听器或 Git diff 伪造完整快照。
- [ ] 回合执行过通用命令时持久化 `has_uncovered_command_effects`。
- [ ] GUI 确认弹窗显示未覆盖副作用警告。
- [ ] CLI 预览和确认显示相同警告。
- [ ] 自然语言权限卡显示相同警告。
- [ ] 撤销成功文案不误称进程、网络、数据库、Git 远端等副作用已恢复。

## 8. 预检和冲突

- [ ] 预检只通过会话和回合查询权威文件集合。
- [ ] 每个文件的节点类型、存在状态、大小、SHA-256、符号链接和工作区身份被检查。
- [ ] 平台可靠提供时，基本权限、File ID/卷标识和硬链接计数也进入后置指纹；不可获取能力有显式标记。
- [ ] 任一文件冲突时不生成可执行令牌。
- [ ] 冲突时整轮零文件写入。
- [ ] 用户处理文件后可重新预检，结果来自新的实际检查。
- [ ] 冲突结果使用结构化原因，前端不解析人类文本。
- [ ] GUI、CLI 和后端不存在强制覆盖选项。

## 9. 确认令牌

- [ ] 令牌使用安全随机值，数据库仅保存哈希。
- [ ] 令牌绑定会话、回合、工作区、操作类型、检查点版本和指纹集。
- [ ] 令牌过期、单次消费，服务重启后无效。
- [ ] 令牌绑定随机进程 `boot_id`，仅持久化哈希不能让旧令牌跨重启复活。
- [ ] 消费令牌与检查点 `record_version` 使用 compare-and-swap；锁内重算指纹成功后才消费。
- [ ] 文件变化、跨会话、跨回合和重放令牌全部被拒绝。
- [ ] 执行时在工作区锁内重新检查全部文件后才消费令牌。
- [ ] 原始令牌不进入日志、GUI 事件、CLI 输出、聊天历史或模型工具结果。

## 10. 多文件恢复事务

- [ ] 执行前保存“用户点击撤销之前”的全部恢复快照。
- [ ] 所有目标阶段文件在修改目标前写入、刷新并校验。
- [ ] 普通文件通过同目录原子替换恢复。
- [ ] 本轮新建文件先进入隔离位置，不立即不可恢复删除。
- [ ] 每个文件应用前再次检查当前状态。
- [ ] 每个文件应用后立即校验目标状态并持久化进度。
- [ ] 只有全部文件最终验证通过后才提交 `reverted`。
- [ ] 数据库提交后才发送 GUI/CLI 成功事件。
- [ ] 文档和 UI 没有误称跨文件操作系统级单次原子性。
- [ ] 已撤销回合重复调用幂等，不再修改文件。

## 11. 崩溃与恢复

- [ ] 在事务的每个状态边界和第 N 个文件处有故障注入测试。
- [ ] 应用重启时将未终态操作标记为 `interrupted`，不自动重放文件写入。
- [ ] 中断操作影响路径及会间接影响它的父/子路径操作被冻结，判定不只比较字符串相等。
- [ ] 中断恢复期间，星瑶在该工作区的通用终端命令也被拒绝。
- [ ] 中断时只读查询和恢复详情仍可用。
- [ ] `continue_revert` 有独立预检、影响展示和一次性令牌。
- [ ] `cancel_revert` 有独立预检、影响展示和一次性令牌。
- [ ] 每次 continue/cancel 创建带 `parent_operation_id` 的独立操作，成功后原子设置父操作 `resolved_by_operation_id`，旧尝试不被覆盖。
- [ ] 跨检查点父子关系和恢复操作循环被拒绝。
- [ ] 两种恢复入口都显式校验 `session_id + operation_id` 归属，跨会话调用被拒绝。
- [ ] 崩溃后文件进入事务未知状态时进入 `recovery_required`，不猜测写入。
- [ ] 中断、恢复完成和需要人工处理的状态在 GUI/CLI 一致。

## 12. 外部修改和并发

- [ ] 预检后、执行前外部修改导致令牌执行失败。
- [ ] 逐文件应用前的外部修改导致后续文件停止并进入中断恢复。
- [ ] 用户界面没有宣传对所有外部进程的绝对原子阻止。
- [ ] 同一规范化工作区的多会话修改/撤销互斥。
- [ ] 受控工具从 prepare 到 write/verify 与撤销使用同一工作区协调器，活跃状态在锁内复核，不存在锁外先查造成的启动竞态。
- [ ] 相对路径、平台大小写、目录符号链接和可识别 UNC 别名不会让同一工作区获得多把锁。
- [ ] 工作区存在主回合或子代理受控修改时撤销返回 `workspace_busy`。
- [ ] 不同工作区能实际并行，没有被一个全局锁串行化。
- [ ] 数据库锁、工作区锁、GUI 队列锁和终端 UI 锁顺序有死锁测试或证明。

## 13. 模型记忆

- [ ] 撤销成功不调用 `undo_last_interaction()`。
- [ ] 原用户消息、assistant 消息、reasoning、工具参数、工具结果和 diff 字节未被改写。
- [ ] 只有文件最终验证成功后才提交“已撤销”纠正记录。
- [ ] 纠正记录在应用重启后仍存在。
- [ ] 同一规范化工作区的其他会话能看到相关纠正，不同工作区不会串入。
- [ ] `build_dynamic_prompt` 包含回合失效事实、影响文件、重读要求和未撤销副作用。
- [ ] 纠正信息没有进入稳定 system prompt 破坏前缀缓存。
- [ ] 中断撤销的动态上下文不误称“已撤销”，而是提示工作区可能不一致。
- [ ] 后续相关回合实际重读当前文件，不盲信旧 diff。

## 14. GUI

- [ ] `turn_start` 及本轮消息/diff 具有权威 `turn_id`。
- [ ] `TurnGroupInfo` 和 `ChangedFilesPanel` 按 `turn_id` 绑定撤销状态。
- [ ] 会话历史使用批量撤销状态查询，没有 N+1 Bridge 请求。
- [ ] 回合进入 `ready` 后，卡片使用持久化最初 `before` -> 最终 `after` 的权威净 diff 和净增删统计，不累加临时过程 diff。
- [ ] 历史文件 diff 按归属检查点的 `file_id` 惰性加载，前端不能用任意路径读取快照。
- [ ] 撤销后和重启后仍可从 before/after blob 查看原回合净 diff；二进制文件仅显示安全摘要。
- [ ] 卡片展开区和撤销按钮是独立交互元素，没有嵌套 `<button>`。
- [ ] 没有因模仿截图新增无需求的“审核”占位功能。
- [ ] `ready`、`no_changes`、检查中、`conflicted`、`reverting`、`recovering`、`reverted`、`interrupted`、`failed`、`unavailable` 及生命周期与快照过期的组合显示正确。
- [ ] `reverted + snapshot expired` 仍显示已撤销，只将原 diff 标记为过期。
- [ ] 确认弹窗显示恢复数、删除新建文件、恢复删除文件、聊天保留和未覆盖副作用。
- [ ] 撤销非最新回合时显示后续完成回合数量和语义依赖警告，不声称自动理解跨文件依赖。
- [ ] 冲突弹窗不显示强制执行，明确本次零文件修改。
- [ ] 成功后卡片显示“已撤销”，原 diff 仍可查看且标识为原修改。
- [ ] 刷新页面、切换会话和重启应用后卡片状态一致。
- [ ] 重复点击不会发生重复撤销操作。
- [ ] 键盘、焦点恢复、ARIA 和 reduced motion 符合现有前端规范。
- [ ] `evaluate_js` 只通过 `gui-js-dispatcher`，不在 `_delta_lock` 内调用 JS 桥。
- [ ] `turn_undo_updated` 只更新对应会话和回合，不串到当前正在查看的其他会话。

## 15. CLI

- [ ] 回合结束后显示文件数、增删数、文件摘要和实际 `/undo <turn_id>` 指引。
- [ ] 文件过多时正确截断展示而不丢失撤销集合。
- [ ] 没有创建规格之外的 `/review` 命令。
- [ ] `/undo`、`/undo <turn_id>`、`list`、`preview`、`status` 和 `recover` 正常工作。
- [ ] `/undo` 无参数只选择最近 `ready` 回合，跳过 `no_changes`、运行中、不可用和已撤销回合；后台任务以独立 ID 和来源标签列出。
- [ ] `/undo` 默认确认为 `N`。
- [ ] 不存在 `--force`、永久 `--yes` 或将人机确认令牌写入命令行/日志的非交互执行旁路。
- [ ] 短 `turn_id` 歧义时拒绝并要求完整 ID。
- [ ] 冲突输出显示预期和当前状态，并明确零文件修改。
- [ ] 已撤销重复调用显示原撤销时间并保持幂等。
- [ ] 中断输出包含操作 ID、已处理文件和恢复指引。
- [ ] 后台线程使用 prompt_toolkit 主线程安全调度，不直接渲染。
- [ ] GUI 撤销后 CLI 立即读到相同持久化状态，反之亦然。
- [ ] CLI 撤销非最新回合时显示与 GUI 一致的后续回合依赖警告。

## 16. 自然语言工具与权限

- [ ] 明确撤销请求使用结构化 `undo_turn` 工具，不让模型根据旧 diff 自行反向编辑。
- [ ] 工具只接受最近回合或明确 `turn_id`，不接受任意文件路径。
- [ ] 工具没有 `force`、忽略冲突或部分撤销参数。
- [ ] 权限管线在文件写入前显示服务预检影响。
- [ ] 自然语言权限卡显示后续完成回合数量和语义依赖警告。
- [ ] 用户拒绝权限后零文件修改。
- [ ] 模型不看到一次性确认令牌。
- [ ] 工具返回结构化结果摘要，失败时不自动调用文件工具补救。
- [ ] 新工具接入前后运行 Provider byte-golden 和 prompt byte-stability。
- [ ] 没有为迁就实现擅自改写黄金字节基线。

## 17. 旧功能迁移

- [ ] GUI 不再调用 `undo_last_edit(force=True)`。
- [ ] CLI `/undo` 不再执行旧单文件逻辑。
- [ ] `/checkpoint restore` 对新检查点调用 `TurnUndoService`。
- [ ] 旧检查点没有被伪造成新安全格式，不可用时有明确说明。
- [ ] 旧 `--force` 恢复路径已删除或不可达。
- [ ] `LAST_UNDO_STATE`、`undo_last_edit()` 的单文件恢复逻辑和 GUI `undo_last_edit` Bridge 入口已在完整交付中删除；如保留同名废弃适配器，它只报迁移错误且不写文件。
- [ ] 不存在旧、新两个撤销系统同时对同一回合写文件。

## 18. 安全与隐私

- [ ] 撤销能力不是通用任意路径 `sandbox_bypass()`。
- [ ] 恢复权限限定为检查点中已登记路径。
- [ ] 冲突、恢复和快照错误不会被脱敏成无法诊断的模糊成功。
- [ ] 日志不包含原始文件内容、令牌、凭据和不必要的工作区外路径。
- [ ] Harness Journal 不写入文件内容、工具参数、工具结果、令牌或凭据。
- [ ] 快照内容不通过 GUI 事件或 Bridge 接口无限制暴露。
