## 二、全局约束（承接既有约定）

1. **双端兼容**：任何机制不得假设用户在哪一端（GUI/CLI）。
2. **字节稳定红线**：不得改变 `build_stable_prompt` 的字节输出；不得为通过测试修改 `tests/test_prompt_byte_stability.py` 与 `tests/test_provider_payload_golden.py`。
3. **不引入第三方依赖**（特别是解析类库；复用现有实现）。
4. **新增配置字段默认=现行为**；唯一例外：T1 的敏感环境变量默认排除（安全默认，任务内标注，并在 `更新说明.md` 记录）。
5. **Harness 纪律**：Journal 不落正文；新增审计/日志字段只准 ID 与元数据。
6. **分支与提交**：只在 `dev` 分支；每个任务独立提交；不混杂无关重构。
7. **模块划分/技术栈/公共接口不变**：只允许"新增文件 / 新增函数 / 新增字段 / 新增配置"。
8. **验证纪律**：不得把未执行或环境受限的验证写成通过；每任务完成 = 相关测试通过 + 既有回归面无新增失败。

Windows 下统一使用：`venv\Scripts\python -m pytest <路径> -v`
