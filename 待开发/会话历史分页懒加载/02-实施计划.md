## Task 1: memory 层分页查询 `get_history_paged`

**文件：**
- 修改：`core/memory.py`（在 `get_history_with_ids` 附近新增方法）
- 测试：`tests/test_history_paged.py`（新建）

**接口：**
- 产出：`ChatMemoryManager.get_history_paged(session_name: str, before_id: int | None = None, limit: int = 50) -> tuple[list[dict], bool]`
  - 返回 `(messages, has_more)`；messages 为正序、经 `_parse_message_rows(rows, with_ids=True)` 解析（每条带 `_msg_id`）。
  - 会话不存在返回 `([], False)`。

**实现骨架：**

```python
def get_history_paged(self, session_name, before_id=None, limit=50):
    """分页读取会话历史（含 _msg_id），按 id 正序返回本页。

    before_id=None 取最新一页；否则取 id < before_id 的一页。
    分页边界对齐回合起点：本页最旧一条非 user 且仍有更早消息时，
    向前扩展至最近一条 user（上限 limit+30）。
    返回 (messages, has_more)。
    """
    with self._lock:
        cursor = self.conn.cursor()
        cursor.execute('SELECT id FROM sessions WHERE session_name = ?', (session_name,))
        row = cursor.fetchone()
        if row is None:
            return [], False
        session_id = row[0]

        max_fetch = max(1, int(limit)) + 30
        if before_id is None:
            cursor.execute(
                'SELECT id, role, content FROM messages WHERE session_id = ? '
                'ORDER BY id DESC LIMIT ?', (session_id, max_fetch))
        else:
            cursor.execute(
                'SELECT id, role, content FROM messages WHERE session_id = ? AND id < ? '
                'ORDER BY id DESC LIMIT ?', (session_id, int(before_id), max_fetch))
        fetched = cursor.fetchall()          # 倒序：最新在前
        if not fetched:
            return [], False

        page = fetched[:int(limit)]
        extra = list(fetched[int(limit):])   # 倒序的扩展余量
        # 回合对齐：本页最旧（page[-1]）非 user 时，沿更早方向吞并 extra 直到 user 或耗尽
        while extra and page[-1][1] != 'user':
            page.append(extra.pop(0))

        oldest_id = page[-1][0]
        cursor.execute(
            'SELECT EXISTS(SELECT 1 FROM messages WHERE session_id = ? AND id < ?)',
            (session_id, oldest_id))
        has_more = bool(cursor.fetchone()[0])

        page.reverse()                        # 回到正序
        return self._parse_message_rows(page, with_ids=True), has_more
```

**前置接口（Task 1 产出）：** `memory.get_history_paged(session_name, before_id, limit) -> (messages, has_more)`。

**改动点：**

1. 文件顶部常量区附近加：`HISTORY_PAGE_SIZE = 50`。
2. `_load_session_messages(self, session_name, before_id=None, limit=HISTORY_PAGE_SIZE)`：
   - 内部改调 `get_history_paged`；返回值改为 `(msgs, has_more, oldest_id)` 三元组。
   - **`oldest_id` 取未过滤的本页最旧消息的 `_msg_id`**（roles 过滤会丢 system 消息，游标必须以 DB 行 id 为准，否则翻页漏消息）。
   - 逐条映射逻辑（strip_context_suffix/sanitize/media/turn_links）原样保留。
   - `_get_session_last_error` 附加逻辑仅在 `before_id is None` 时执行。
   - 异常分支返回 `([], False, None)`。
3. 新增桥接方法：

```python
def load_older_messages(self, session_name: str, before_id: int) -> Dict[str, Any]:
    try:
        before_id = int(before_id)
    except (TypeError, ValueError):
        return {"ok": False, "messages": [], "has_more": False, "oldest_id": None}
    if before_id <= 0:
        return {"ok": True, "messages": [], "has_more": False, "oldest_id": None}
    names = {s.get("name") for s in self._memory.get_all_sessions(workdir=None, include_empty=True)}
    if session_name not in names:
        return {"ok": False, "messages": [], "has_more": False, "oldest_id": None}
    msgs, has_more, oldest_id = self._load_session_messages(session_name, before_id=before_id)
    return {"ok": True, "messages": msgs, "has_more": has_more, "oldest_id": oldest_id}
```

4. **搜全 `_load_session_messages` 的既有调用方**（`get_initial_state` 等），本任务只改签名，调用方在 Task 3 适配——为防中间态报错，本任务可让 `get_initial_state` 临时解构（`msgs, _, _ = ...`）保持可运行，Task 3 再接入元信息。

**测试：**

- 首页（before_id=None）：返回 ≤ limit+30 条、三元组结构、oldest_id 为本页最小 `_msg_id`；
- last_error 只附加在首页（mock 一个带错误的会话，翻页响应无 error_note 附加）；
- `load_older_messages`：正常翻页 / 最后一页 has_more=False / before_id=0、负数、非数字、会话不存在 四种防御分支；
- 游标不漏消息：含 system 消息的会话，两页拼接后 id 连续无洞。

**改动点：**

2. state：`historyHasMore = false`、`historyOldestId: number | null = null`、`historyLoading = false`。
3. `switchSession` 成功分支写入三个状态（`res.history_oldest_id ?? null`）。
4. 新 action：

```ts
async loadOlderMessages() {
  if (!this.historyHasMore || this.historyLoading || !this.historyOldestId) return;
  const sessionAtCall = this.currentSession;
  this.historyLoading = true;
  try {
    const res = await api.load_older_messages(sessionAtCall, this.historyOldestId);
    if (sessionAtCall !== this.currentSession) return; // 竞态丢弃
    if (res?.ok) {
      const older = adaptHistoryMessages(res.messages || []); // 复用 switchSession 的历史适配管线（tool 配对等）
      this.messages = [...older, ...this.messages];
      this.historyHasMore = !!res.has_more;
      this.historyOldestId = res.oldest_id ?? null;
    }
  } finally {
    if (sessionAtCall === this.currentSession) this.historyLoading = false;
  }
}
```

（适配函数名以 appStore 现有实际为准——365 行附近有历史消息 tool_call 配对逻辑，prepend 必须走同一管线。）

**测试：** prepend 顺序正确 / 状态更新 / 单飞守卫（并发两次只发一次请求）/ 竞态丢弃（请求中切会话，返回不污染新会话）/ has_more=false 后不再请求。

function onChatScroll() {

async function maybeLoadOlder() {
  const el = chatScrollRef.value;
  if (!el || el.scrollTop >= 120) return;
  if (!store.historyHasMore || store.historyLoading) return;
  const oldHeight = el.scrollHeight;
  const oldTop = el.scrollTop;
  await store.loadOlderMessages();
  await nextTick();
  el.scrollTop = el.scrollHeight - oldHeight + oldTop; // 位置补偿，不跳动
}
