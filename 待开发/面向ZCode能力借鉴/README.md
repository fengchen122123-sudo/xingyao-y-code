# 面向 ZCode 的能力借鉴工作包（精选三项）

状态：待开发（本文档仅为设计规格，未经用户明确同意不得开始开发）
设计日期：2026-09-21
目标：为星瑶补充三项「与界面形态无关、属纯能力缺失」的机制——Hooks 体系、上下文注入分类治理、工具调度拓扑化。

## 为什么只有三项

前序分析（见 `待开发/借鉴ZCode工程治理/`）经过三轮修正后收敛。筛选标准：

1. **必须是能力缺失**，不是「ZCode 有、星瑶没有」的数量差；
2. **必须与界面形态无关**——星瑶是 GUI 优先，ZCode 是终端优先，它的 CLI 特性不是星瑶的缺口；
3. **必须是星瑶现有机制无法覆盖的**。

最终入选三项：

| # | 项 | 类型 | 为什么入选 |
|---|---|---|---|
| 1 | Hooks 体系 | 可扩展性 | 星瑶完全空白，且与界面无关（"改完文件自动格式化"在哪端都需要） |
| 2 | 上下文注入分类治理 | 上下文治理 | 星瑶已有 `cache_keepalive` 投入，这是同一套思路的另一半 |
| 3 | 工具调度拓扑化 | 执行效率 | 星瑶 `ToolSpec` 已有 6 个安全字段，只缺调度算法 |

**被排除的项及理由**（记录在此，避免重复讨论）：

| 项 | 排除理由 |
|---|---|
| 自定义斜杠命令 | CLI 专属；GUI 已有技能 / MCP / 插件三套更自然的扩展入口 |
| 输出风格预设 | 与 `core/persona_settings.py` 人设体系功能重叠 |
| 插件 marketplace | 单人维护不现实；技能体系已覆盖主要价值 |
| LSP 深化 | `find_definition` 已覆盖 agent 最常用场景 |
| 大结果落盘 | `core/tool_cache.py` 已缓解重复读取成本，收益有限 |
| 会话分叉 | 与 `core/turn_undo/` 部分重叠 |
| 插件 sensitive 标记 | 价值小，已在 `core/hidden_secret` 类机制中部分覆盖 |

## 三项之间的依赖关系

```
上下文注入分类治理（02）
        │
        │  Hooks 的额外上下文注入需要一个统一的注入通道
        ▼
    Hooks 体系（01）

工具调度拓扑化（03） —— 完全独立
```

**结论**：03 可以随时开始（零依赖）。02 应先于 01（01 依赖 02 的注入通道），但 01 也可先用临时通道实现、后续迁移。

## 不可改变的产品决定

1. **三项都必须与 GUI/CLI 双端兼容**。任何机制不得假设用户在哪一端。
2. **行为等价优先**。03 的调度改造对「无依赖声明」的输入必须产生与现有 `group_tool_batches()` **完全一致**的执行顺序。
3. **缓存亲和不可破坏**。02 的改造不得使 `build_stable_prompt` 的字节输出发生任何变化（有 `test_prompt_byte_stability.py` 的 sha256 golden 守着）。
4. **安全优先**。01 必须带信任机制——项目级 hook 配置随仓库 clone 而来，等同执行他人代码。
5. **不引入第三方依赖**。特别是不得引入 YAML 解析库（复用 `core/skills.py` 的 frontmatter 解析）。
6. **每项独立可验收、独立可回滚**。
7. **不做 MVP 或分版交付**；按完整设计实现，实施过程可拆分提交。
