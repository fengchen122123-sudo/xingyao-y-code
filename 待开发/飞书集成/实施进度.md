## 三、规格与现实的差异

### 差异 1（T2）：假设 A3 不成立 → 手写帧编解码，新增依赖降为 0

计划里 A3 是「用官方 `protobuf` 包替换上游夹带的 protobuf 副本」，因此原计划要新增
一个依赖 `protobuf`。**实测否证**：上游 `pbbp2_pb2.py` 是 protoc 3.19 之前的老式生成
代码（手工构造 `_descriptor.FileDescriptor` / `Descriptor`），官方 protobuf ≥4.21 直接
拒绝加载：

```
$ venv/Scripts/python.exe -m pip install protobuf && python -c "import pbbp2_pb2"
ImportError: ... Descriptors cannot be created directly.
If this call came from a _pb2.py file, your generated code is out of date and must be
regenerated with protoc >= 3.19.0. ... 1. Downgrade the protobuf package to 3.20.x or lower.
```

（实验后已 `pip uninstall protobuf` 并清理残留的空 `google` 命名空间目录，环境还原。）

**处置**：改为自写 `core/feishu/_lark_ws/frame.py`——该协议只有 2 个消息、9 个字段，
且只用 varint 与长度前缀两种线格式，手写约 300 行、零依赖、可完整单测（含黄金字节
对照 protobuf 线格式）。上游夹带的 `pb/google/protobuf/**`（约 50 个文件）与
`pbbp2_pb2.py` / `gogo_pb2.py` 均不搬运。

**结果**：本次集成对 `requirements.txt` 的改动为 **零**（原计划新增 1 个 `protobuf`），
比计划更贴近「不影响其它功能」的目标；`websockets` 版本未动。
