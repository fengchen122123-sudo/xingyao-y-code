## 1. 背景

星瑶目前具备：

- GUI（pywebview + Vue3）与 CLI 双端，多会话并行，每会话回合互斥（`gui_bridge.py:526` `_turn_start_lock`）；
- 会话忙时消息自动排队、回合结束自动补发（`gui_bridge.py:530` `_message_queues`，前端 `messageQueues` 幂等替换）；
- 三种「程序化发起回合」的现成先例：后台命令总结（`gui_bridge.py:4608` `_start_bg_command_summary`）、后台子代理汇总（`gui_bridge.py:4693` `_maybe_start_bg_summary_turn`）、LAN 远程注入（`core/lan_server.py:425` `dispatch_rpc`，`turn_source` 强制 `lan`）；
- 回合外事件推送先例：后台任务完成回调（`gui_bridge.py:4580` `_on_background_task_finished`，经 `emit_event` 直接推前端）；
- 应用可最小化到托盘驻留：回合运行时关窗弹出三选框，选「是」即隐藏窗口继续运行（`core/gui_lifecycle.py:99-182`）；
- 完善的权限体系：`decide_permission`（`core/permission_policy.py:36`）+ 单活跃请求 broker（`core/permission_broker.py:263`）+ GUI PermCard；`accept_edits` / `full` 档位已存在（`core/permission_policy.py:75-84`）；
- 按回合撤销（turn_undo）可为自动化回合生成检查点。

当前缺失：用户没有任何手段让星瑶「到点自己干活」。`core/task_scheduler.py` 是计划项依赖调度器（按依赖关系认领计划项），与时间调度无关；全仓库没有任何 cron/定时/自动化触发代码。本规格补齐这一块。

## 2. 目标

- 用户可以在 GUI 中创建/编辑/启停/删除自动化任务：任务 = 名称 + 触发器 + 目标会话 + 提示词 + 无人值守权限档位 + 错过策略。
- 触发器 v1 支持：固定间隔（每 N 分钟）、每天定时（HH:MM）、每周指定星期几定时、每次应用启动时；任何任务都可用「立即执行」手动触发。
- 调度引擎在 GUI 进程内常驻，到点后把任务提示词作为一次**真实 agent 回合**投递到目标会话，全程可中断、可留痕、可按回合撤销。
- 每次触发留下运行记录（queued/running/completed/cancelled/error/skipped/interrupted + 时间 + 错误），GUI 可按任务查看历史。
- 无人值守安全：`confirm` 档位下权限请求立即自动拒绝并记录；`accept_edits` / `full` 需用户显式为该任务选择。
- 运行结束、被跳过、出错时向用户推送应用内通知；非当前会话的运行通过会话状态点可见。
- 与现有机制零冲突：排队、权限、计划状态机、turn_undo、缓存保活、多会话并行全部按既有行为工作。

## 3. 非目标（明确不做，防止范围蔓延）

- **Cron 表达式**：v1 用 interval/daily/weekly 三种结构化触发器覆盖绝大多数需求，五段 cron 解析器列为二期扩展。
- **CLI 端托管引擎或 `/automation` 命令**：二期另行立项（见 README 产品决定 7）。
- **系统级调度**：不写 Windows 任务计划程序、不自启、不开机拉起；应用关闭期间定时器不存在。
- **文件监视触发、webhook/LAN 触发自动化任务**：二期。
- **自动重试/退避**：失败的运行绝不自动重跑，用户手动「立即执行」或等下一次正常触发。
- **多步骤工作流编排**：一个任务就是「一条提示词 + 一个触发器」，不引入 DAG；复杂编排是计划状态机（core/plan.py）的职责。
- **系统级托盘气泡通知**：v1 只用应用内 notice；托盘 `Icon.notify()` 列为二期增强。
- **修改请求构造**：不改 system prompt、tools schema、metadata、`extra_body`、Prompt Ledger 与缓存亲和材料（AGENTS.md 铁律；自动化提示词只是普通 user 消息）。

## 4. 核心产品原则

### 4.1 应用内调度原则

引擎随 GUI 进程存活，随 `ApiBridge.shutdown` 终止。UI 必须明示「仅应用运行期间生效」；应用未运行错过的触发不补跑（除非该任务 `missed_run_policy = run_once`，且最多补一次，见 8.4）。

### 4.2 复用回合管线原则

自动化触发 = 在既有约束下「替用户发一条消息」：

- 复用 `_start_bg_command_summary`（`gui_bridge.py:4608`）确立的内部回合模式：`internal_kind="automation"`，`turn_start` 事件带 `internal` 标记，前端以系统样式渲染；
- 用户消息正文 = 任务提示词**逐字原文**，经 `_memory.add_message` 正常落库（运行痕迹、上下文压缩、按回合撤销全部自然成立）；
- 回合串行化、消息排队、取消、权限、turn_undo 检查点全部按既有行为工作，不为自动化开特例通道。

### 4.3 无人值守权限安全原则

- 自动化回合的权限请求若落到 ASK（`confirm` 档位普通变更、敏感变更、沙盒外等），由桥层**立即自动拒绝**：不弹 PermCard、不无限等待（这与人工回合「绝不因用户离开自动拒绝」的产品规则刻意不同，是自动化专属规则）；
- 自动拒绝必须留下痕迹：notice 通知 + 运行记录；
- `accept_edits` / `full` 只能由用户在任务表单显式选择，保存时前端必须展示风险说明；任务创建后的编辑改档同样确认；
- 档位语义完全复用 `decide_permission`（`core/permission_policy.py`），不发明新的权限判定。

### 4.4 显式失败原则

- 触发器配置非法 → 保存即拒绝并列出全部错误；
- 目标会话不存在 → `ensure_session` 重建同名空会话后继续（与 `send_user_message` 行为一致），并在运行记录中保留 session_name；
- 分发异常 → 运行记录标 `error`，引擎继续服务其他任务，绝不因单任务异常停摆；
- 任何静默降级、吞异常、自动重试都视为实现错误。

### 4.5 取消不复活原则

用户停止一个自动化回合 = 普通回合取消：运行记录标 `cancelled`，不注入接手指令、不自动重跑、不进重试队列（对齐 AGENTS.md 取消语义铁律与 Harness 崩溃恢复铁律）。

### 4.6 线程纪律原则

- 引擎线程（`automation-engine`，daemon）只做：读钟、SQLite 记录、CAS 认领、在 `_turn_start_lock` 内做入队/启动判定。绝不发起 LLM 请求、绝不触碰 JS 桥（推事件一律经 `emit_event` → `_js_queue`，AGENTS.md GUI 线程铁律）；
- 事件 JSON 小而低频（见 11.3），队列满被丢弃时按既有限频日志处理，不做特殊处理。

## 5. 完整功能范围

### 5.1 任务模型

| 字段 | 类型 | 约束 |
|---|---|---|
| id | TEXT (uuid4 hex) | 主键 |
| name | TEXT | 1-50 字符，用户可见，允许重名但保存时提示 |
| enabled | INTEGER (0/1) | 默认 1；禁用任务不触发但保留配置与历史 |
| trigger_type | TEXT | `interval` / `daily` / `weekly` / `startup` |
| trigger_config | TEXT (JSON) | 见 8.1 |
| target_session | TEXT | 目标会话名；允许不存在（触发时重建） |
| prompt | TEXT | 1-6000 字符，逐字作为 user 消息正文 |
| permission_mode | TEXT | `confirm`（默认）/ `accept_edits` / `full` |
| missed_run_policy | TEXT | `skip`（默认）/ `run_once` |
| created_at / updated_at | TEXT (ISO) | |
| last_run_at | TEXT (ISO) / NULL | 最近一次实际触发时间 |
| next_run_at | REAL (unix ts) / NULL | `startup` 任务恒 NULL |

上限：任务总数 ≤ 64（保存时拒绝第 65 个并提示）。`run_automation_task_now` 对禁用任务可用（手动执行不受 enabled 限制），对 `startup` 类型同样可用。

### 5.2 触发器语义

- `interval`：距上次认领 `interval_minutes` 分钟后触发；以「认领时刻 + 间隔」计算下一次，允许长回合导致的自然漂移（不做对齐补齐）。
- `daily`：每天本地时间 `HH:MM`；已过当日时刻则取明天。
- `weekly`：每周指定星期几（ISO weekday，1=周一 … 7=周日）的本地时间 `HH:MM`；一次可勾选多个星期。
- `startup`：引擎每次启动（应用启动/重启）时触发一次，不重复。
- 任何任务均可手动「立即执行」（trigger_kind=`manual`），不改变 `next_run_at`，不重置周期。
- 触发种类枚举（运行记录 `trigger_kind`）：`scheduled` / `startup` / `manual` / `catchup`（补跑）。

### 5.3 调度引擎

- 模块：`core/automation/engine.py`，类 `AutomationEngine`，单实例归属 `ApiBridge`。
- 线程：daemon，名 `automation-engine`；由 `gui_main` 在窗口创建后显式 `api.start_automation_engine()` 启动（`gui_main.py:499` 创建桥之后），**不在 `ApiBridge.__init__` 内自启**（测试可构造桥而不起线程）。
- 主循环（伪代码，实现须等价）：

```python
def _loop(self):
    while not self._stop.is_set():
        now = self._time_fn()
        claimed = self._storage.claim_due_tasks(
            now, compute_next_run,
            include_startup=self._first_iteration,   # 首轮认领 startup 任务
            catchup_enabled=self._first_iteration,   # 首轮按 8.4 处理过期触发
        )
        for task, run_id, trigger_kind in claimed:
            try:
                self._dispatch(task, run_id, trigger_kind)   # = bridge._dispatch_automation_run
            except Exception as exc:            # 单任务失败不停摆
                self._storage.finish_run(run_id, "error", f"分发失败: {exc}")
        self._first_iteration = False
        timeout = self._next_wake_timeout(now)  # 最近 next_run_at-now，夹在 [0, POLL_SECONDS=30]
        self._wake.wait(timeout)
        self._wake.clear()
```

- 唤醒：任务的增/改/删/启停/手动执行后，桥层调用 `engine.notify_changed()` 置 `_wake`，使变更即时生效（不必等 30s 轮询）。
- 单飞判定：`claim_due_tasks` 认领前检查该任务是否已有 `queued/running` 状态的运行记录；有则写入一条 `skipped`（error="上一次运行尚未结束"）并继续计算 `next_run_at`，**不**派发。
- 停止：`stop()` 置停止位、置醒事件、`join(timeout=5)`；幂等。挂接点：`ApiBridge.shutdown`（`gui_bridge.py:997`）在置 `_shutting_down` 之后、取消各会话 `_cancel_events` 之前调用，保证收尾期间不再有新触发。

### 5.4 执行管线（触发 → 回合 → 收尾）

新增桥方法（`gui_bridge.ApiBridge`）：

```python
def _dispatch_automation_run(self, task: dict, run_id: str, trigger_kind: str) -> None
```

流程（全部在引擎线程执行，拿 `_turn_start_lock` 完成判定+动作）：

1. `display_text = f"自动化任务「{task['name']}」"`；
2. 持 `_turn_start_lock`：
   - 若 `_is_turn_active(target_session)`：把条目 `{"id": uuid, "text": task["prompt"], "display_text": display_text, "attachments": None, "automation_run_id": run_id, "automation_permission_mode": task["permission_mode"]}` 追加进 `_message_queues[target_session]`，运行记录保持 `queued`，emit `message_queue` 快照（复用 `_emit_message_queue_snapshot`，`gui_bridge.py:4079`）；
   - 否则：运行记录置 `running`（记 started_at、turn_id 稍后回填），调用 `_spawn_turn_worker(task["prompt"], target_session, internal_kind="automation", display_text=display_text, automation_run_id=run_id, permission_mode_override=task["permission_mode"])`（`gui_bridge.py:4030`）。

`_spawn_turn_worker` / `_run_turn_worker`（`gui_bridge.py:4030/4238`）改动：

- 两函数签名各追加 `automation_run_id: str = ""` 与 `permission_mode_override: str = ""`（默认空串，所有既有调用方零改动）；
- `_run_turn_worker` 末尾收尾：在既有 `finish_once()` 发出 `turn_finish` 之后，若 `automation_run_id` 非空，按结果写运行终态——`_consume_turn_events` 返回 cancelled → `cancelled`；过程中捕获到异常 → `error`（附错误摘要）；否则 → `completed`。终态写入必须 exactly-once（用局部旗标防 finish 路径重入）。
- `turn_id` 回填：worker 取得 turn_id（`gui_bridge.py:4404`）后把运行记录的 turn_id 更新，供追踪与排查。
- `_drain_message_queue`（`gui_bridge.py:4089`）：补发时把条目中的 `automation_run_id` 与 `automation_permission_mode` 透传给 `_spawn_turn_worker`；对无该键的既有条目默认空串（旧排队消息零影响）。补发成功后把对应运行记录 `queued → running`。
- 用户消息落库：`_run_turn_worker` 既有逻辑（`gui_bridge.py:4418` `_memory.add_message(...)`）不变——提示词逐字入 `messages` 表。

### 5.5 无人值守权限策略

- 回合请求构造：`prepare_turn_messages(..., permission_mode=...)`。接线：`_run_turn_worker` 在 `gui_bridge.py:4460` 附近当前统一传 `self._current_permission_mode`；改为：`permission_mode_override` 非空（自动化回合，随 5.4 的 worker 参数传入）则用它，否则维持既有行为。人工回合零改动。
- ASK 自动拒绝：`_activate_permission_request`（`gui_bridge.py:3747`）入口处新增判断——若请求的 `permission_owner`（= turn_id）属于某条 `running` 状态的自动化运行：
  1. 从请求选项中定位拒绝/取消项索引，`permission_broker.resolve(request_id, deny_index)`；定位失败则 `permission_broker.cancel_owner(turn_id)`（`core/permission_broker.py:155/200`）；
  2. emit `notice`：`自动化任务「{name}」无人值守已自动拒绝权限请求：{工具名}`；
  3. **不**发 `permission_request` 事件（PermCard 不弹）；
  4. 既有「权限确认无限等待」注释（`gui_bridge.py:3780`）补充说明：该规则仅适用于人工回合。
- 自动拒绝计数：运行记录无需新字段，错误摘要不需要；notice 即可。若一轮内 ASK 被拒导致 agent 终止属正常业务结果（`completed`）。
- 桥层维护 `self._automation_active_run_turns: dict[str, str]`（turn_id → run_id），由 5.4 的登记/收尾维护；权限判断 O(1)。

### 5.6 运行历史、恢复与清理

- 状态机：`queued → running → completed | cancelled | error`；旁路终态 `skipped`（单飞）、`interrupted`（恢复）。
- 启动恢复：引擎启动时 `storage.recover_stale_runs()` 把上个进程遗留的 `queued/running` 批量置 `interrupted`（error="应用重启，运行中断"），**绝不自动重跑**（对齐 Harness 崩溃恢复铁律）。
- 过期触发处理（`missed_run_policy`）：引擎启动时对 `next_run_at < now - 60s` 的启用任务：
  - `skip`（默认）：仅把 `next_run_at` 重算到未来，留一条 `skipped`（error="应用未运行，触发已过期"）；
  - `run_once`：以 `trigger_kind="catchup"` 派发一次（仍走单飞判定），然后重算 `next_run_at`。
- 清理：每次插入运行记录后按任务保留最近 50 条（超出删除最旧）。
- 任务删除：删除任务同时删除其运行记录（用户主动行为，无需确认级联保护以外的机制；GUI 删除任务已有确认弹窗）。

### 5.7 通知

- 运行终态（completed/cancelled/error/skipped）后 emit `notice`（`gui_bridge.py:4987` 同款），文案含任务名、触发种类与结果；`completed` 仅在该任务开启了「完成通知」（v1 默认关，`notify_on_success` 字段并入 trigger_config 外的任务级配置，默认 0）时提示，`error/skipped` 恒提示。
- 非当前会话的运行复用既有会话状态点（`sessionStatusDots`），无需新机制。
- 全部走 `emit_event` 单通道，LAN 端同步自动生效。

## 7. 数据模型

### 7.1 建表（挂到桥既有 `self._memory` 同一 MemoryManager/DB；建表模式仿 `core/turn_undo/storage.py:73`）

```sql
CREATE TABLE IF NOT EXISTS automation_tasks (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    enabled INTEGER NOT NULL DEFAULT 1,
    trigger_type TEXT NOT NULL,
    trigger_config TEXT NOT NULL,
    target_session TEXT NOT NULL,
    prompt TEXT NOT NULL,
    permission_mode TEXT NOT NULL DEFAULT 'confirm',
    missed_run_policy TEXT NOT NULL DEFAULT 'skip',
    notify_on_success INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    last_run_at TEXT,
    next_run_at REAL
);
CREATE INDEX IF NOT EXISTS idx_automation_tasks_next_run
    ON automation_tasks (enabled, next_run_at);

CREATE TABLE IF NOT EXISTS automation_runs (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL,
    task_name TEXT NOT NULL,          -- 冗余快照，任务删除后历史仍可读（随任务删除，防御性保留）
    trigger_kind TEXT NOT NULL,
    status TEXT NOT NULL,
    session_name TEXT NOT NULL,
    turn_id TEXT,
    error TEXT,
    queued_at TEXT NOT NULL,
    started_at TEXT,
    finished_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_automation_runs_task
    ON automation_runs (task_id, queued_at DESC);
```

所有 SQLite 操作沿用项目惯例：写后 `conn.commit()`；时间戳一律 ISO 本地时间字符串，`next_run_at` 用 unix 秒（REAL）便于比较与 CAS。

## 8. 触发时间计算规则（core/automation/scheduling.py，纯函数）

```python
def parse_hhmm(value: str) -> tuple[int, int]: ...          # "HH:MM"，非法抛 ValueError
def validate_trigger(trigger_type: str, config: dict) -> list[str]: ...   # 返回全部错误，空列表=合法
def compute_next_run(trigger_type: str, config: dict, now_ts: float) -> float | None:
    ...
```

- `interval`：`config = {"interval_minutes": int, 1 ≤ n ≤ 10080}` → 返回 `now_ts + n*60`。
- `daily`：`config = {"time": "HH:MM"}` → 今天该时刻；已过则明天。本地时间（`datetime.fromtimestamp(now_ts).replace(...)` → `.timestamp()`）。
- `weekly`：`config = {"time": "HH:MM", "weekdays": [1..7] 去重升序}` → 从今天起 8 天窗口内第一个 weekday 命中且晚于 now 的时刻；`weekdays` 为空非法。
- `startup`：返回 `None`（无计划时刻）。
- 边界必须测试：daily 恰好等于当前分钟（视为已过，取明天）、interval=1 分钟、weekly 周界翻转、`compute_next_run` 恒返回严格大于 `now_ts` 的值（防 0 秒死循环）。
- 时区/DST 简化：全部按本地墙钟计算，不做时区切换补偿；文档向用户说明。

### 8.4 过期判定的统一口径

「错过」定义：引擎启动时 `next_run_at < now - 60`（60 秒为正常调度抖动容差）。补跑最多一次（`run_once`），补跑后照样重算 `next_run_at`，不会连环补。

## 9. 并发与一致性

| 竞争点 | 机制 |
|---|---|
| 同任务重复触发 | `next_run_at` CAS 单条 UPDATE（7.2），认领成功才写 run 行 |
| 同任务上轮未结束 | `has_active_run` 单飞判定 → `skipped` |
| 引擎 vs 用户编辑任务 | 认领快照 task dict 派发；编辑写入新行值，正在跑的运行按旧提示词完成（与回合开始后消息不可变的项目原则一致） |
| 引擎 vs 会话回合 | `_turn_start_lock` 内判定+入队/启动（与 `send_user_message` 同一把锁，`gui_bridge.py:526`）；忙时走 `_message_queues` |
| 引擎线程 vs 关机 | `stop()` 先于 `_cancel_events` 批量置位（5.3）；运行中的自动化回合随既有取消路径收尾为 `cancelled` |
| SQLite 并发 | 沿用 MemoryManager 既有连接与事务纪律；引擎写操作短小（毫秒级），与回合落库无锁竞争风险 |
| 权限自动拒绝 vs 用户响应竞态 | `resolve` 幂等（broker 单活跃请求语义）；自动化判定在 emit `permission_request` 之前完成，不存在双通道 |

## 12. 异常处理

| 场景 | 行为 |
|---|---|
| 触发器配置非法 | 保存拒绝，返回全部错误；绝不入库 |
| 目标会话不存在 | `ensure_session` 重建（与 `send_user_message` 一致），正常运行 |
| 引擎分发抛异常 | 该 run 置 `error`（"分发失败: …"），循环继续 |
| LLM/回合错误 | 既有 `turn_error` 路径收尾，run 置 `error`（错误摘要截断 500 字符） |
| 用户停止回合 | run 置 `cancelled`，不重放 |
| 应用崩溃/强杀 | 下次启动 `recover_stale_runs` → `interrupted` |
| DB 写失败 | 显式抛出并记日志；引擎本轮跳过该任务，不吞异常 |
| 任务数超上限 / prompt 超长 | 保存拒绝，可读文案 |
| JS 队列满事件被丢 | 既有丢弃+限频日志；前端打开页面时 `get_automation_tasks` 全量拉取自愈 |

## 16. 风险与开放问题

1. **`full` 档位被滥用于无人值守**：缓解——表单内联风险说明 + notice 留痕 + 每次触发目标会话可见全文。接受残余风险，由用户显式选择。
2. **每日定时跨夏令时/手动改钟**：本地墙钟简化可能少跑/多跑一次；已列入文档说明，不做补偿。
3. **长回合占会话导致触发顺延**：interval 从认领时刻起算 + 单飞跳过，语义确定为「不堆积」；用户若要严格节奏可在目标会话专用化。
4. **`_message_queues` 条目新增键**：补发路径必须透传，测试已覆盖；若未来该结构重构，`automation_run_id` 键契约写入本规格 5.4。
5. **与 turn_undo 的交互**：自动化回合生成检查点，用户可按回合撤销自动化改动——这是特性而非风险；验收清单含对应场景。
